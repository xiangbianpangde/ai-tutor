## 一、环境级根因：死系统代理（影响半天里所有怪症状）

Windows 系统代理 `127.0.0.1:7897`（Clash，注册表 ProxyEnable=1）进程失联。
httpx/urllib 在 Windows 会读注册表代理（不只环境变量），于是：

- DeepSeek 判分/enrich 全部 `WinError 10054` → llm_scorer **静默降级启发式**
  （这是挑战 4 第一轮"全走启发式"的原因，也意外暴露了回退路径缺陷）；
- 新版 mineru CLI 起本地 mineru-api 后 HTTP 健康检查被代理劫持 → 假死超时；
- uv 装包连不上 pypi。

**绕法（进程级，不动系统设置）**：`NO_PROXY=localhost,127.0.0.1,api.deepseek.com`；
uv 加 `--index-url https://pypi.tuna.tsinghua.edu.cn/simple`。已写入持久记忆
（dead-system-proxy-workaround）。

**运维含义**：教学时代理一死，判分会无声降级。FIX-L 之前这意味着"复读概念名=correct
0.7 + 冷启动白拿 0.88 先验"；FIX-L 之后降级判分封顶 partial 且 evidence 明示降级。

## 二、FIX-L：判分启发式回退永不授 correct（挑战 4 产物）

**攻击设计**：3 个真实概念（fastapi KG 只读取出：依赖项/响应状态码/HTTP 中间件），
每概念配对两答案——极简正确（57-93 字，不复述概念名）vs 同内容注水（271-309 字，
复述题目含概念名）。

**LLM 主路径（DeepSeek 直连）**：3/3 极简版 correct（0.95/0.90/0.90），注水版
0.95/0.90/0.95——**无压短抬长**，R-16 冗长偏好在生产判分路径未复现。
判分记录：`data/scorer_attack_results.json`。

**回退启发式（第一轮误打误撞实测）**：2/3 极简正确被压 partial 0.4，注水版反而
correct 0.7——根因：旧启发式只看"答案与概念名 2-gram 重叠"，复述题目=送分，
甚至"我不知道X是什么"也判 correct。**修复**（`llm_scorer._heuristic_score`）：
- 启发式无法核实语义 → **永不授 correct**（主题相关 partial 0.5 / 不相关 partial 0.4 /
  空 incorrect 不变）；主题相关性同时看概念名与定义/通俗解释 n-gram（消除不对称）；
- evidence 明示"LLM 不可用降级判分"，建议恢复后重答。

**连锁修改（红→绿过程，如实记录）**：
- `test_llm_scorer.py`：2 条旧断言 correct→partial（行为有意变更）+ 新增 3 条 FIX-L
  回归（含名废话不得 correct / 极简不低于注水 / 降级必须明示）；
- `test_cold_start_server.py`：3 条测试原依赖"概念名作答→启发式 correct→种 0.88
  先验"的漏洞通道，改为显式 Mock 判分器给 correct（保留测试本意），+ 新增 1 条
  FIX-L 回归：无 LLM 时含名作答 `seeded_mastered == []`（不发掌握认证）；
- `BDD/test_bdd_ai_tutor.py`：2 条（涨掌握度/BKT 收敛）同改 Mock 判分器。
  全量跑过程：794 passed 2 failed（BDD 两条）→ 修复 → **797 passed**。

## 三、FIX-M：论文/文档骨架节名过滤（挑战 2 产物）

**体裁选择**：用户自有 AAAI 论文 PDF（英文学术+数学公式）——离线可跑（代理死，
web 采集不可靠；视频工具链缺席），且骨架形态是博客语料从未出现的。

**管线**：mineru 解析 8/8 页 → md_translator 17 块 DeepSeek 翻译 →
`aaailunwenyandu-47a1d90454` 语料（18 节）→ build(full)。

**第一次全量扫描（19 概念）**：禁类 = 骨架节名 `摘要`/`致谢`/`参考文献` 3/19 =
**15.8% > 5% 红线**（FIX-K 12 类规则均不覆盖此形态）。边缘类（结构性弱概念，
不计禁类）：引言/结论/相关工作/实验/实验设置/实验结果。

**FIX-M**（`kg_enrich_adapter._NOISE_DOC_SKELETON_RE`）：只杀无歧义纯骨架
（摘要/abstract/致谢/acknowledgments/参考文献/references/bibliography/目录/附录A/
appendix B/索引/版权声明/免责声明/作者简介）；**引言/结论/相关工作保留**（常含实
质内容，宁留弱概念不误杀），含实名附录章（"附录A 矩阵代数基础"）不受影响。
回归测试：`test_build_toc_skips_paper_skeleton_titles`（FIX-K 测试一字未动）。

**重建后第二次全量扫描（16 概念）**：禁类 **0/16 = 0% < 5%** ✅。16 个名字全量列出
于审计输出（MemoryART 主题/三种记忆/数据集/评估/实验系列/消融/引言/结论/相关工作）。

**回灌 M-014 的新发现**：
1. 骨架节名是体裁性噪声——每换一种体裁就会有新形态（博客 12 类 → 论文骨架），
   枚举式过滤的天花板再次验证，内容级抽取仍是正解（开发清单 C2 波红线已挂）；
2. **类别失衡跨体裁复现**：博客语料 98% method → 论文语料 100% definition，
   失衡是抽取层系统性问题而非语料偶然；
3. 关系抽取 LLM 返回截断无法解析（warning 实录），关系回落结构边——疑似
   max_tokens 截断，留给 M-014/M-008 修。

**附带验证**：mineru 工具环境曾整体腐烂（缺 six/scipy/ftfy/einops/pyclipper +
transformers 5.9.0 与 UnimerNet 公式识别不兼容）——逐个补齐 + 降 transformers==4.57.6
后 8 页含公式论文解析通过；修复链已写入持久记忆（external-tools-stage3）。
tutor_cli 曾把 TutorError 的 hint（含外部 CLI stderr 尾巴）吞掉导致三轮盲猜，
已修：错误输出追加 `[hint]` 行。
