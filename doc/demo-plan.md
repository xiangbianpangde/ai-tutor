# 教育专家演示方案 — 计划

> 目标：向教育专家合作者清晰展示 ai-tutor 的核心教学能力
> 架构：Claude Desktop（操作端）+ Streamlit 仪表盘（可视化端）并行
> 原则：不修改现有生产代码

---

## 1. 演示需要展示什么

教育专家关心的不是技术实现，而是 **6 个教学能力**：

| # | 能力 | 专家会问的问题 | 用什么证明 |
|---|------|-------------|----------|
| 1 | 知识组织 | "系统怎么知道知识结构？" | 可视化 KG：概念节点 + 关系边 |
| 2 | 掌握度量化 | "怎么知道学生学会没？" | BKT p_mastery 数值 + 分布图 |
| 3 | 策略非固定 | "不同学生怎么区别教？" | 策略选择器决策树展示 |
| 4 | 状态感知 | "系统看得出学生走神了？" | 心流级别 + 调节器调参 |
| 5 | 结构化产出 | "学完留下了什么？" | 知识骨架（前提→逻辑→结论→易错点） |
| 6 | 长期规划 | "48h 怎么执行的？" | 5 Phase 进度 + 章节里程碑 |

## 2. 演示架构

```
┌──────────────────┐    同一 SQLite      ┌──────────────────┐
│  Claude Desktop  │    data/tutor.db    │  仪表盘 (浏览器) │
│  (你操作教学)     │ ◄──────────────►  │  (投影给专家看)  │
│                  │                     │                  │
│  自然语言驱动     │                     │  实时可视化内部  │
│  4 个 MCP server │                     │  只读不写不操作  │
└──────────────────┘                     └──────────────────┘
```

仪表盘不调用 MCP server，只读数据库，零侵入。

## 3. 仪表盘结构（6 个 Tab）

### Tab 1：教学会话 — 展示策略 + 心流
- 当前概念 ID + 掌握度进度条
- 降阶法步骤条：🎯GOAL→🔍REDUCE→❌COMPLEMENT→🧩RECONSTRUCT→✅REVIEW
- 当前策略 + 状态
- 心流级别彩色指示灯（🔴SILENT→💜IMMERSED）
- 调节器参数卡片（难度系数、脚手架、原子数、错误数）
- 最近 10 轮交互历史

### Tab 2：掌握度 — 展示 BKT
- 全部概念的掌握度柱状图（绿 >0.85 / 黄 0.4-0.85 / 红 <0.4）
- 统计指标：总数、平均掌握度、已掌握数、薄弱数
- 薄弱概念列表

### Tab 3：心流与调节 — 展示状态感知
- 心流级别变化折线图
- 5 级心流定义说明表
- 调节器修正逻辑说明
- PGFGA 10 信号定义

### Tab 4：知识图谱 — 展示知识组织
- 选择当前 KG
- 概念总数 / 关系总数
- 按章节的概念分布柱状图
- 关系类型分布柱状图
- 低置信度概念列表

### Tab 5：知识骨架 — 展示结构化产出
- 已产出的骨架卡片列表（前提→逻辑→结论→易错点）
- 骨架结构模板说明

### Tab 6：里程碑 — 展示长期进度
- 5 Phase 各自进度条
- 总掌握度
- 里程碑验收标准清单

### 技术选型

| 项 | 选择 |
|---|------|
| 框架 | Streamlit（纯 Python，2 天可搭，不依赖前端工具链） |
| 图表 | Altair（Streamlit 原生支持，交互式缩放） |
| 数据源 | 同 SQLite，只读不写 |
| 刷新 | 2 秒自动轮询 + 手动刷新按钮 |
| 额外依赖 | `streamlit`, `altair`, `pandas`（装用户环境，不改 pyproject） |

## 4. 演示脚本（12 分钟流程）

### 4.1 开场（30s）

> "ai-tutor，48 小时学完一科。我在 Claude Desktop 操作后端教学服务，
> 这边仪表盘实时展示系统内部状态。我们走一轮实际教学。"

### 4.2 建知识图谱（2min）

Claude Desktop 操作：`build_knowledge_graph(corpus_id=..., depth=concept)`

仪表盘 Tab 4：概念数涨到 N，关系类型分布出现，低置信度标出。

> "教材进来后，系统先建知识图谱。每个概念有定义、难度、前置依赖。
> 后续所有教学决策都基于这张图——不是基于关键词匹配。"

### 4.3 摸底（1min）

Claude Desktop 操作：`start_learning_session()`

仪表盘 Tab 2：部分概念出现绿条（摸底跳过），其余保持灰色。

> "先出 10 题摸底。已掌握的概念自动跳过。48 小时可行
> 不是因为教得快，而是因为不教你已经会的东西。"

### 4.4 教学循环（5min）

Claude Desktop 操作：一轮 respond

仪表盘 Tab 1：步骤条从 GOAL→REDUCE→...逐步推进。Tab 2 掌握度上升。

> "降阶法 4 步：定义目标 → 拆原子问题 → 排除错误理解 → 让学生自己建骨架。
> 每一步的推进都依赖学生回答，不是系统自顾自讲。"

### 4.5 展示心流调节（2min）

故意答错 2-3 次。仪表盘 Tab 1 心流从🟢FLUENT 掉到🟡SHALLOW，调节器参数变化。

> "连续答错后系统检测到心流下降，自动降低难度、增加脚手架。
> 这就是调节器的作用——在心流断裂之前主动调整。"

### 4.6 展示骨架产出（1min）

一个概念走完降阶法后，仪表盘 Tab 5 出现骨架卡片。

> "这个骨架是学生自己组织出来的——前提、逻辑、结论、易错点。
> 系统不给标准答案，而是引导学生用自己的话产出知识结构。"

### 4.7 展示长期进度（30s）

Tab 6 显示 5 Phase 进度。

> "48 小时分 5 个阶段，系统自动规划进度、插复习、做休息提醒。
> 你看到的是 Phase 2 偏微分学的进度。"

## 6. 风险

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| Streamlit 刷新与 MCP 写入错位 | 中 | 数据滞后几秒 | 手动刷新按钮兜底 |
| 专家看 UI 而非教学能力 | 中 | 注意力偏移 | 演示前说明"这是看内部状态的" |
| 现场环境缺依赖 | 低 | 仪表盘起不来 | 准备纯 Claude Desktop 演示预案 |
