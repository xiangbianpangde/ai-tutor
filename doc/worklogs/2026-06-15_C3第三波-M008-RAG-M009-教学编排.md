## 做了什么

### M-008 RAG 引擎（`backend/rag/`，commit 88b8031）

设计包 FF-M-008 要 ChromaDB + DeBERTa-v3-large-mnli。死系统代理下两者都装不上/跑不动，
且当前阶段（核心引擎就位）要的是可端到端跑通+可测+确定性，不是规模化向量召回。
**务实落地**（决策见 ADR-0003）：

- `types.py`：Chunk / RouteDecision / ValidationResult / RetrieveResult（纯 dataclass，可序列化）
- `retriever.py`：`LexicalRetriever`（idf 加权 token 重叠，BM25-lite）；中文 tokenize 产
  单字 + bigram；`ChunkSource` Protocol（`KGChunkSource` 读概念表 / `StaticChunkSource` 测试）
  ——换向量后端只换 source，engine 不动（OCP）
- `validator.py`：`AnswerValidator`，NLI 风格答案-引用源一致性。LLM 法官可注入；回退启发式
  **永不过度授信**（无源不支撑 / 置信封顶 0.6 / 法官挂自动降级不抛）——沿用 FIX-L 教训
- `routing.py`：`KeywordRouter` 抽 query 内容关键字
- `engine.py`：`RAGEngine` 编排 routing→retrieval→**重检索循环（≤3 轮自主放宽召回）**→
  状态机 IDLE→RETRIEVED→SCORED→VALIDATED/CANNOT_CONFIRM；缓存(M-005)/事件(M-006)可注入；
  BM25 绝对分经 `_normalize_score` 归一到 [0,1] 作 NLI 代理信号
- REST：`POST /api/knowledge/rag/query|validate`（透明披露 rounds/confirmed/top_score）
- 21 测试（tokenize / 检索 / 验证含"永不过度授信"红线 / 状态机 / REST）

### M-009 教学编排（`backend/teaching/`，commit 1668490）

把 v1 `TeachingEngine`（L6：策略状态机/BKT/心流/判分/错误诊断）包成 REST 可驱动的会话编排，
**不重写决策、只搬运 + 接线**：

- `orchestrator.py`：`TeachingOrchestrator`.start（`engine._topo_order` 定首概念 → 建会话 →
  首动作）/ next_action / respond / advance / transition
- engine 工厂可注入——测试用 `FakeEngine` stub，免建真 KG/真 LLM/碰演示资产
- 经 M-004 SessionManager 共享会话存储（新建会话自动进 `list_sessions`，已测）+ 摘要刷新
- 经 M-006 EventBus 发 `teaching.session_started/responded/action`
- REST：`POST /sessions/start|{id}/respond|{id}/advance|{id}/transition` + `GET /{id}/next-action`
- 9 测试（编排单元含真落库验证 + kg_id 从 Subject 解析 + 事件 + REST 全链）
