# 设计文档：总体架构

> 涉及模块：全部。这是本次重构的顶层架构设计。

## 背景

当前架构是 4 个独立 MCP Server（knowledge / tutoring / digest / sync）通过 stdio/SSE 挂载到 Claude Desktop。核心问题：

- **无法独立运行**：必须通过 Claude Desktop 或其他 MCP Host 中转（问题 #21）
- **MCP 协议不适合教学**：持续多轮对话场景下调用不稳定（问题 #4）
- **4 个进程各自为政**：虽共享 SQLite，但无法做统一的会话管理、缓存、监控
- **无前端 UI**：只有一个简陋 dashboard，可视化等于零（问题 #3）

## 目标

1. **独立运行**：用户双击 exe 即启动，无需安装 Claude Desktop 或任何 MCP Host
2. **架构清晰**：内部保持 knowledge/tutoring/digest/sync 四大模块边界，但统一到一个后端进程
3. **实时通信**：教学场景用 WebSocket 双向通信，管理操作用 REST API
4. **离线优先**：核心教学逻辑纯本地计算，LLM 仅在需要时调 API

### 进程模型

```
Electron Main Process
  ├── spawn Python backend (child_process)
  │     └── uvicorn main:app --port 18501
  ├── 等待 backend health check 通过
  ├── 创建 BrowserWindow → load React app
  └── 窗口关闭 → kill Python 子进程
```

### 通信协议

| 场景 | 协议 | 说明 |
|------|------|------|
| 知识库管理（采集/建图/查询） | REST | 请求-响应，适合工具式操作 |
| 教学对话（回答/下一题/打断） | WebSocket | 双向实时，低延迟 |
| 产物生成（digest） | REST + 轮询 | 异步任务，返回 task_id 轮询状态 |
| 同步（Obsidian/git） | REST | 请求-响应 |
| 状态面板数据 | WebSocket | 实时推送概念/心流/进度变更 |

## 影响范围

- **新增**：`backend/`、`frontend/` 两大目录
- **迁移**：`shared/` → `backend/core/`；`servers/*/` → `backend/engines/*/`
- **删除**：`fastmcp` 依赖；MCP tool 装饰器
- **保留**：`data/`（SQLite schema 不变）、`doc/`（文档）、`scripts/`（demo 脚本）
- **新增依赖**：FastAPI、uvicorn、websockets；Electron、React、Vite、ECharts

## 风险

| 风险 | 概率 | 缓解 |
|------|------|------|
| Python 嵌入 Electron 体积过大 | 高 | PyInstaller 打包，预计 150-200MB，可接受 |
| 现有 672 测试需适配新架构 | 高 | 按模块逐批迁移，保留旧测试文件至全部通过 |
| WebSocket 断连导致教学中断 | 中 | 前端自动重连 + 后端 session 持久化（断点续传） |
| LLM API 调用费用不可控 | 中 | 前端展示 token 消耗 + 设置预算上限 + 缓存命中减少调用 |
| 旧 MCP tool 逻辑迁移遗漏 | 中 | 交叉对照表逐 tool 迁移，每迁移一个跑对应测试 |
