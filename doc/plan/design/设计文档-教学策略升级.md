# 设计文档：教学策略升级 + 健康监控 + 幻觉检测

> 涉及模块：`backend/engines/tutoring/strategies/`、`backend/middleware/health_monitor.py`、`backend/engines/tutoring/fact_checker.py`、`backend/engines/tutoring/rule_engine.py`
> 解决问题：#2(降阶法分页), #10(休息提醒), #12(费曼法), #16(阶段过渡), #18(幻觉), #20(规则约束)

## 背景

现有教学引擎虽然 7 种策略 + 心流 + 增益回路全部可用，但存在以下具体缺陷：

- **降阶法第一阶要读 5 万行 MD**（#2）：`jiangjie.py` 直接把整个 KG 的所有概念扔给 LLM，没有分页
- **费曼法只有精简状态机**（#12）：`feynman.py` PROMPT→WAIT→EVALUATE→PASS，缺少 fidelity 五维评估、引导修正循环
- **阶段过渡无缓冲**（#16）：Phase 切换时直接进入新概念，没有交叉复习
- **无休息提醒**（#10）：`pace_controller.py` 只在认知负荷过高时反馈，不追踪学习时长
- **长期使用出现强幻觉**（#18）：LLM 生成的内容没有事实核查
- **AI 凭理解运行**（#20）：教学决策全靠 LLM，缺少硬编码规则兜底

## 目标

- 降阶法支持分页加载（首次 ≤200 行摘要，按需展开）
- 费曼法升级到完整状态机（含 fidelity 五维评估 + 引导修正循环）
- Phase 切换时插入缓冲（前 3 个概念交叉复习上一 Phase）
- 新增 HealthMonitor：学习时长追踪 → 番茄钟 → 强制休息弹窗
- 新增 FactChecker：KG 交叉验证 + 外部搜索确认
- 新增 RuleEngine：教学规则硬编码兜底 LLM

## 方案

### 1. 降阶法分页修复

```python
# backend/engines/tutoring/strategies/jiangjie.py

class JiangjieStrategy:
    MAX_CONCEPTS_PER_STAGE = 5  # 每阶段最多展示 5 个概念

    def _build_goal(self, concepts: list[Concept]) -> str:
        """GOAL 阶段：只展示知识骨架摘要（≤200 行），不是全部概念正文。"""
        skeleton = []
        for c in concepts[:self.MAX_CONCEPTS_PER_STAGE]:
            skeleton.append(f"- {c.names[0]}：{c.informal_description[:100]}")
        return f"本阶段学习骨架：\n" + "\n".join(skeleton)

    def _expand_concept(self, concept_id: str) -> str:
        """按需展开：学生点击某概念时，才加载完整正文。"""
        concept = self.kg.get(concept_id)
        return concept.definition + "\n" + concept.examples
```

# backend/engines/tutoring/strategies/feynman.py

class FeynmanStrategy:
    """完整费曼学习法状态机。

    States:
        INTRO → EXPLAIN → SELF_CHECK → FIDELITY_EVAL
          → PASS (掌握)
          → GUIDED_CORRECTION → EXPLAIN (修正后重讲，最多3轮)
          → SIMPLIFY → EXPLAIN (降维重讲)
          → MODEL → SELF_CHECK (教师示范)
    """

    FIDELITY_DIMENSIONS = [
        "concept_accuracy",    # 概念是否正确
        "logic_completeness",  # 逻辑是否完整
        "language_clarity",    # 表达是否清晰（无术语堆砌）
        "example_relevance",   # 举例是否贴切
        "boundary_awareness",  # 是否知道"不适用场景"
    ]

    def evaluate_fidelity(self, student_explanation: str, concept: Concept) -> FidelityReport:
        """LLM 五维评估 + 每维给 0-1 分 + 一句话建议。"""
```

class TeachingEngine:
    def _transition_phase(self, from_phase: int, to_phase: int):
        """在 Phase N 结束后，Phase N+1 开始前，插入缓冲期。"""
        buffer_concepts = self._pick_buffer_concepts(from_phase, n=3)
        # 缓冲期：交叉复习上一 Phase 的薄弱概念
        for c in buffer_concepts:
            self._insert_review_node(c, mode="quick_quiz")
        # 缓冲结束后才进入新 Phase
```

### 4. HealthMonitor（休息提醒）

```python
# backend/middleware/health_monitor.py

class HealthMonitor:
    """学习健康监控：番茄钟 + 休息提醒。"""

    POMODORO_WORK = 25 * 60     # 25 分钟
    POMODORO_BREAK = 5 * 60     # 5 分钟
    LONG_BREAK_AFTER = 4        # 4 个番茄钟后长休息
    LONG_BREAK = 15 * 60        # 15 分钟

    def tick(self, session_id: str):
        """每秒调用。检测是否到休息时间。"""
        elapsed = self._session_elapsed(session_id)
        if elapsed >= self.POMODORO_WORK and not self._on_break(session_id):
            return BreakSuggestion(
                type="pomodoro",
                message=f"已经连续学习 {elapsed//60} 分钟，休息一下吧 ☕",
                break_duration=self.POMODORO_BREAK,
            )

    # 注意：这与已有的 pace_controller（认知负荷 → 节奏调整）是互补关系
    # pace_controller: "你答错很多题了，慢一点"
    # health_monitor:   "你连续学了 25 分钟了，休息一下"
```

    """对 LLM 生成的教学内容做事实核查。"""

    def check(self, content: str, context_concepts: list[Concept]) -> FactCheckResult:

        # 2. 公式检查：提取 LaTeX 公式 → 与 KG 中的公式对比
        # 3. 逻辑一致性：前提→推理→结论 是否自洽

        """检查一个教学陈述是否与 KG 中的概念定义一致。"""

教学引擎在 `respond` 的 `next_action` 前插入事实核查：

```python
def respond(self, session_id, answer):
    ...
    next_action = self.strategy.next_action(...)
    # 事实核查（仅对 explain 类型动作）
    if next_action.type == "explain":
        check_result = self.fact_checker.check(next_action.content, context)
        if not check_result.passed:
            next_action.content = check_result.corrected_content
```

### 6. RuleEngine（规则约束层）

```python
# backend/engines/tutoring/rule_engine.py

class RuleEngine:
    """硬编码教学规则，兜底 LLM 决策。优先于策略选择器。"""

    RULES = [
        # 规则 1：已掌握概念绝不再教
        Rule("skip_mastered", condition=lambda ctx: ctx.mastery > 0.85,
             action="skip"),

        # 规则 2：连续 3 次错误 → 强制降阶，不管策略选择器怎么说
        Rule("force_reduction", condition=lambda ctx: ctx.consecutive_errors >= 3,
             action="switch_to_reduction"),

        # 规则 3：前置概念未掌握 → 禁止教下游概念
        Rule("prereq_gate", condition=lambda ctx: not ctx.prereqs_mastered,
             action="teach_prereq_first"),

        # 规则 4：概念 A 的常见误解必须覆盖
        Rule("misconception_coverage", condition=lambda ctx: ctx.misconceptions_uncovered,
             action="insert_misconception_warning"),
    ]

    def evaluate(self, context: TeachingContext) -> RuleResult:
        """规则引擎逐条评估，命中即返回 action（不依赖 LLM）。"""
```

## 风险

| 风险 | 缓解 |
|------|------|
| FactChecker 误杀正确的 LLM 输出 | 核查结果标注置信度，低置信度仅提示、不拦截 |
| RuleEngine 规则与策略选择器冲突 | RuleEngine 优先级最高（硬约束），策略选择器在软约束域工作 |
| 费曼法五维评估 LLM 评分不稳定 | 保留精简版作为 fallback，五维评估失败时降级 |
