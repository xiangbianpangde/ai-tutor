# 设计文档：中间件层

> 涉及模块：`backend/middleware/`（SessionManager / FileManager / CacheLayer / Monitor）

## 背景

当前项目缺少 4 个关键中间件能力（对应问题 #5, #6, #7, #11）：

1. **无统一会话管理**：SessionContext 存在但仅单会话，无法切换/列表/自动过期
2. **无统一文件管理**：data/ 下几十个 UUID 目录，corpora/output/test_mineru 混杂
3. **无缓存层**：每次 LLM 调用都直接请求，相同的概念富化/判分重复消耗 token
4. **无质量监控**：检索质量、回答质量、学习效果没有追踪记录

## 目标

- **SessionManager**：多会话并行，自动摘要 + token 计数，7 天 TTL 自动过期
- **FileManager**：按 `{user}/{subject}/{type}/` 组织文件，禁用 UUID 目录名
- **CacheLayer**：SQLite 表做 L1 缓存，LLM 相同输入命中直接返回
- **MonitorMiddleware**：记录每次检索/回答质量，生成质量报表

## 方案

### 1. SessionManager

```python
# backend/middleware/session_mgr.py

class SessionManager:
    """多会话管理器。"""

    def list_sessions(self, user_id: str) -> list[SessionSummary]:
        """返回用户的所有会话列表（含摘要）。"""
        # summary: 科目名 / 已掌握N/M / 最后活跃时间 / token消耗

    def switch_session(self, user_id: str, session_id: str) -> SessionContext:
        """切换到指定会话。保存当前会话状态，加载目标会话。"""

    def auto_summarize(self, session_id: str) -> str:
        """LLM 生成会话摘要（学过的概念/薄弱点/下一步）。"""

    def cleanup_expired(self) -> int:
        """清理 7 天未活跃的会话。"""

    def token_usage(self, session_id: str) -> TokenReport:
        """本会话的 token 消耗统计。"""
```

新增数据库表：

```sql
CREATE TABLE session_summaries (
    session_id TEXT PRIMARY KEY,
    user_id TEXT NOT NULL,
    subject_id TEXT NOT NULL,
    summary TEXT,                    -- LLM 生成的摘要
    concepts_covered TEXT,           -- JSON array
    token_usage INTEGER DEFAULT 0,
    last_active_at TIMESTAMP,
    expires_at TIMESTAMP,            -- 7 天 TTL
    FOREIGN KEY (session_id) REFERENCES sessions(id)
);
```

### 3. CacheLayer

```python
# backend/middleware/cache_layer.py

class CacheLayer:
    """SQLite 实现的 L1 LLM 缓存。

    缓存键 = hash(provider + model + messages + temperature)
    TTL = 24h（概念定义类）/ 1h（判分/讲解类）
    """

    def get(self, provider: str, messages: list[dict], temp: float) -> str | None: ...
    def set(self, provider: str, messages: list[dict], temp: float, response: str): ...
    def stats(self) -> CacheStats:  # 命中率 / 节省 token 数
        ...
```

预期效果：概念定义类缓存命中率 > 60%，判分类缓存命中率 > 30%，节省 30-40% token 消耗。

## 影响范围

- **新增**：`backend/middleware/` 4 个文件 + 对应测试
- **新增表**：`session_summaries`、`cache_entries`、`monitor_records`
- **修改**：`backend/core/storage.py` FileStore 替换为 FileManager
- **修改**：engine.py 接入 SessionManager、MonitorMiddleware

## 风险

| 风险 | 缓解 |
|------|------|
| 缓存键碰撞（不同输入同hash） | 用完整 messages JSON 做键，sha256 碰撞概率可忽略 |
| 会话摘要 LLM 额外消耗 token | 摘要仅在会话关闭时生成一次，且可关闭 |
| 监控记录膨胀 | 定期归档 > 30 天记录到压缩 JSON |
