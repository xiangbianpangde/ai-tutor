# 设计文档：数据管线

> 涉及模块：`backend/pipeline/`、`backend/engines/knowledge/`
> 外部依赖：research-tool（`../调研/research-tool/`）、pdf2zh（`C:/Users/yhn/pdf2zh/`）
> 解决问题：#1(调研/清洗), #9(重检索), #14(本地资料), #17(中文论文), #19(pdf2zh)

## 背景

v1 的 `acquisition_adapter.py` 极其简陋：PDF 仅 subprocess 调 mineru、web 源直接抛异常、没有清洗管线。
v1 遗留了一份 [`PDF2ZH-CORE-PLAN.md`](../../PDF2ZH-CORE-PLAN.md) 计划把 pdf2zh 拆成核心库供 import，但从未执行。

v2 不再重复造轮子——直接复用两个成熟的外部项目：
- **research-tool**：6 阶段管线（Collect→Deepen→Clean→Extract→Organize→Report），10 搜索源，P1/P2 高级检索
- **pdf2zh**：MinerU PDF 解析 + 并发翻译（DeepSeek/Ollama/LM Studio）

AI-Tutor 的管线是**薄 orchestration 层**，不是重新实现。

## 目标

- AI-Tutor 不自己写采集/清洗/结构化代码——全部委托 research-tool 和 pdf2zh
- 对外统一入口：用户拖入 PDF/输入 URL/粘贴主题 → 自动选引擎 → 输出干净 Markdown
- PDF 处理走 pdf2zh（保留公式/表格/图片），网页检索走 research-tool（10 源 + 反偏差深挖）
- 两个外部项目的失败各自有优雅降级路径

## 方案

### 1. 各来源走哪个引擎

| 来源 | 引擎 | 流程 |
|------|------|------|
| 中文 PDF | pdf2zh (MinerU) → AI-Tutor Structurer | 解析出 MD → 章节检测 → KG Builder |
| 外文 PDF | pdf2zh (MinerU + 翻译) → AI-Tutor Structurer | 解析 + 翻译 → 中文 MD → KG Builder |
| Markdown/TXT | 直读 | 跳过解析，直接进 Structurer |
| 网页 URL | research-tool (Collect→Clean) | 抓取→去噪→去重→相关性过滤 → MD |
| 搜索主题 | research-tool (Collect→Deepen→Clean) | 10 源搜索→反偏差深挖→清洗 → MD |
| 视频 | AI-Tutor 自有 (yt-dlp + whisper) | 下载音频→转写→清洗 → MD |
| Obsidian | AI-Tutor sync 引擎 | 已有实现，不变 |

### 2. pdf2zh 集成方式

**结论：不拆 pdf2zh-core。采用 subprocess 隔离调用，但加强错误处理和进度回调。**

v1 的 [`PDF2ZH-CORE-PLAN.md`](../../PDF2ZH-CORE-PLAN.md) 计划把 pdf2zh 拆成核心库供 Python import。
评估后否定——原因：

- pdf2zh 强依赖 MinerU 的模型文件（~7GB），这些模型与 pdf2zh 的 `.venv` 绑定
- MinerU 本身是重量级 CLI 工具，拆成 Python 库意义不大（仍然是 subprocess 调 C++ 推理）
- pdf2zh 的翻译模块（`translate_md.py`）可以直接 import，但它的 `chunk_markdown` + `translate_chunks_concurrent` 只有 ~150 行——v1 已经树内复制到 `md_translator.py`，维护成本低

**v2 方案**：

```python
# backend/pipeline/pdf2zh_adapter.py

class Pdf2ZhAdapter:
    """pdf2zh 适配器。subprocess 隔离，加强错误处理和进度回调。"""

    def __init__(self, mineru_cmd: str = "mineru",
                 pdf2zh_python: str | None = None):
        self.mineru_cmd = mineru_cmd
        self.pdf2zh_python = pdf2zh_python or self._detect_pdf2zh()

    def _detect_pdf2zh(self) -> str:
        """自动探测 pdf2zh 的 Python 环境。"""
        # 1. 环境变量 PDF2ZH_PYTHON
        # 2. C:/Users/<user>/pdf2zh/.venv/Scripts/python.exe
        # 3. 系统 PATH 中的 python

    def parse(self, pdf: Path, output_dir: Path,
              backend: str = "pipeline", lang: str = "ch") -> Path:
        """MinerU 解析 PDF → MD。保留公式/表格/图片引用。"""
        # 等价于 `mineru -p pdf -o output_dir -b pipeline -l ch`
        # 返回值: output_dir/<stem>/auto/<stem>.md

    def translate(self, md_path: Path,
                  model: str = "deepseek-chat",
                  workers: int = 8,
                  base_url: str = "https://api.deepseek.com",
                  api_key: str | None = None) -> Path:
        """翻译 Markdown → 中文 Markdown。并发翻译 + 断点续跑。"""
        # 检测 _zh.md 已存在 → 跳过
        # 调用树内 md_translator（与 pdf2zh 的 translate_md.py 逻辑一致）

    def convert(self, pdf: Path, output_dir: Path,
                translate: bool | None = None,
                **kwargs) -> Path:
        """一键：PDF → (可选翻译) → 中文 MD。自动检测语言。"""
        # translate=None → 自动检测 PDF 语言，中文不翻译，英文翻译
```

**三层降级**：

| 优先级 | 能力 | 缺失时 |
|--------|------|--------|
| 1 | MinerU CLI（pdf2zh 的 .venv） | 公式/表格/图片保留 |
| 2 | PyMuPDF (fitz) | 纯文本提取，公式丢失 |
| 3 | 报错 | "PDF 功能不可用，请安装 pdf2zh" |

### 3. research-tool 集成方式

**结论：Python import（本地路径依赖），已有基础，v2 深度利用全部阶段。**

v1 已通过 `research_adapter.py` 浅层集成（仅 Collect+Clean）。v2 改为全阶段利用：

```python
# backend/pipeline/research_adapter.py (重写)

class ResearchAdapter:
    """research-tool 适配器。全阶段利用。"""

    def acquire_web(self, topic: str, corpus_dir: Path,
                    deep_search: bool = True,
                    facets: list[str] | None = None) -> ResearchResult:
        """网页采集：Collect(10源) → Deepen(反偏差) → Clean(去噪/去重/相关性)。

        deep_search=True: 启用 P2 多排序×多页翻页
        facets: P1 去锚维度（如 ["博士","论文","南洋理工"]）
        """
        config = PipelineConfig(
            stages=["collect", "deepen", "clean"],
            collector=CollectorConfig(
                search_engines=self._select_engines(),
                deep_search=deep_search,
                core_keyword=self._extract_core(topic),
                facets=facets or [],
            ),
            deepen=DeepenConfig(enabled=deep_search),
            cleaner=CleanerConfig(
                relevance_filter=True,
                relevance_threshold=0.4,  # 过滤掉 <40% 相关度的网页
                dedup_similarity=0.85,     # 相似度 >85% 去重
            ),
        )
        pipeline = create_pipeline(config)
        return await pipeline.run(topic)

    def extract_knowledge(self, clean_dir: Path) -> KGSeed:
        """从清洗后的文本抽取知识：Extract(实体/关系) → Organize(知识树)。
        产出可直接喂入 KG Builder 的结构化数据。"""

    def deepen_gaps(self, kg_id: str) -> list[str]:
        """反向传播：检测 KG 稀疏节点 → 生成修正查询 → 追加检索。
        用于 KG 质量迭代。"""

    def search_external(self, query: str, sources: list[str] | None = None) -> list[SearchHit]:
        """外部搜索：用于 Agentic RAG 和 FactChecker。"""
```

**四层利用**：

| 阶段 | research-tool Stage | AI-Tutor 用途 |
|------|-------------------|--------------|
| 资料采集 | Collect → Deepen → Clean | 替代 acquisition_adapter 的 web 源 |
| KG 构建 | Extract → Organize | depth="auto" 模式：自动从文本抽 KG |
| Agentic RAG | Collector.search_only + Deepen | 10 源检索 + 缺口补搜 |
| FactChecker | Collector.search_only | 外部交叉验证教学陈述 |
| KG 迭代 | Backward | 稀疏概念自动补全 |

**降级路径**：

| research-tool 不可用时 | 回退 |
|----------------------|------|
| 整体未安装 | DuckDuckGo 单源搜索 + 基础 HTML→文本清洗 |
| Deepen 失败 | 跳过深挖，Collect 结果直接进 Clean |
| Extract 失败 | 跳过，KG Builder 用 concept/full 模式（LLM 富化） |
| LLM API key 未配 | Clean 的 relevance_filter 关闭（全部保留） |

### 4. AI-Tutor 自有代码的边界

有了 research-tool 和 pdf2zh 后，AI-Tutor 自己的管线代码**大幅精简**：

| 旧代码 | v2 处理 |
|--------|--------|
| `acquisition_adapter.py:_acquire_file()` | 委托 pdf2zh Adapter |
| `acquisition_adapter.py:_acquire_web()` | 委托 research-tool Adapter |
| `pdf_parser.py` | 委托 pdf2zh Adapter，保留 MinerU CLI 直接调用作为 fallback |
| `md_translator.py` | 保留（~150 行，与 pdf2zh 翻译逻辑一致，无额外维护成本） |
| `research_adapter.py` | 重写：全阶段利用 |
| `pipeline/cleaner.py` | **删除**：research-tool 的 Cleaner 更强（MinHash + LLM 相关性） |
| `pipeline/structurer.py` | 保留但精简：只做章节检测 + 公式保护 |

## 风险

| 风险 | 缓解 |
|------|------|
| research-tool 采集到 0 篇 | 自动回退 DuckDuckGo + 提示用户换关键词 |
| pdf2zh MinerU 模型未下载（~7GB） | 首次使用时引导下载，显示进度条 |
| pdf2zh subprocess 找不到 Python | 启动时自动探测，设置页手动配置路径 |
| 两个外部项目版本不同步 | research-tool 用 editable 本地路径（跟随桌面更新）；pdf2zh 用环境变量指定路径 |
| 三层降级后仍失败 | 最终回退到纯文本提取（PyMuPDF）+ 基础搜索（DuckDuckGo），保证核心流程不阻断 |
