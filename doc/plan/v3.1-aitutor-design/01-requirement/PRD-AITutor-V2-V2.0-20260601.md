## 1. 需求背景与目标

### 1.1 背景
[上游] 当前 ai-tutor 形态为 4 个 MCP server（knowledge / tutoring / digest / sync）+ Claude Desktop 宿主。21 个测试发现问题（详见 `doc/发现问题.txt`）已系统性暴露 MCP 架构的瓶颈：MCP 调用不可靠、状态割裂、文件结构混乱、缺乏会话/缓存/监控层、缺乏长期记忆、AI 仅凭"理解"执行引擎而无确定性流程。
[上游] 用户原话："我打算进行重构，变成一个软件，而不是 mcp，同时解决这些问题；注意开发请严格按照 c:\Users\yhn\Desktop\开发规范"。

### 1.2 核心目标
1. **G1（架构目标）** 把 ai-tutor 从"MCP 工具集"重构为"独立可分发软件"——单体后端 + 多端前端（桌面 / Web 可选 / CLI），消除对 Claude Desktop 宿主的强依赖。[上游-21]
2. **G2（问题清零目标）** 21 个发现问题 100% 映射到可追溯的功能点，且每个问题至少有 1 条对应的验收标准。[上游-doc/发现问题.txt]
3. **G3（规范合规目标）** 严格遵循 `开发规范/conventions/`（01-架构 / 02-代码 / 03-Git / 04-API / 05-测试 / 06-文档 / 08-图谱）+ ai-workflow 7 篇流程；交付时附"规范红线覆盖度"自检表。[上游-开发规范]
4. **G4（可分发目标）** 提供 CLI 入口、可选 GUI（**GUI 形态三选一，详见 OC-1 [S-017] 决策项**）、可选 Web；同时保留 Python 库形态供二次开发。[PM推断:依据=用户原话"变成一个软件"+ v2 计划 设计文档-打包发布]
5. **G5（学习能力目标）** 内置费曼学习法、遗忘曲线（**FSRS 算法 [S-002]**）、Agentic RAG（**含复杂度路由 [S-003]**）、缓存/监控/重检索、阶段渐进式过渡、**抗幻觉用 NLI/LLM 法官 [S-012]**，48 小时学完一科的核心承诺保持。[上游-问题 9,12,13,15,16,18]

### 1.3 成功指标
| 编号 | 指标 | 目标值 | 测量方式 |

### 3.1 P0 — 核心必须（≤ 30%）

#### F-001 后端单体化（FastAPI + 单进程）
- 描述：把 4 个 MCP server（knowledge / tutoring / digest / sync）迁移到 `backend/engines/<name>/`，由 FastAPI 单进程承载；保留原 SQLite schema，向后兼容 v1 数据库。
- 优先级：P0
- 用户角色：U1, U3
- 验收标准：① 启动 `ai-tutor serve` 后 `curl /health` 返回 200；② 旧 `data/tutor.db` 拷贝后所有 v1 测试通过；③ **`grep -r "from mcp.server" backend/` = 0（服务端协议引用归零；客户端 SDK 引用允许，作为 MCP 客户端演进）[S-001 采纳理由：竞品 Aider/Continue/LiteLLM 演进路线支持此分层]**。
- 依赖功能：F-002, F-003
- 冲突边界：与"不做 MCP 宿主适配"互斥。
- 关联问题：#4, #21
- 来源：[上游-21问题] + [v2计划-总体架构] + [S-001]

#### F-002 中间件层（Session / Cache / Monitor / Pipeline / RAG）
- 描述：实现 5 类中间件，统一挂在 FastAPI 依赖注入层。Session 支持多会话切换与长期记忆摘要（**短期用 ConversationSummaryBufferMemory；长期用 LangGraph Store+JSON 持久化；实体用 SQLite+sqlite-vec [S-011 采纳理由：Hindsight 达 91.4% LongMemEval，LangGraph Store 标准化]**）；Cache 缓存常见问答与检索结果（**双后端：SQLite 单机模式 + Redis 可选生产模式；语义阈值 0.85~0.95 [S-013 采纳理由：语义缓存可减 40-90% LLM 调用]**）；Monitor 记录每次检索/回答质量（**可观测栈 = structlog + OpenTelemetry Bridge，trace_id 32 位 hex + span_id 16 位 hex [S-016 采纳理由：structlog 性能 2x 优于竞品，OTel 已 stable]**）；Pipeline 串联"预处理→检索→精排→LLM→后处理"；RAG 集成 Agentic + 重检索。
- 优先级：P0
- 用户角色：U1, U4
- 验收标准：① `/api/sessions` 支持 list/switch/delete 至少 3 个会话；② 相同 query 二次请求时 cache hit 率 ≥ 80%；③ `/api/monitor/quality` 返回最近 100 条问答的 quality 指标（字段含 trace_id/span_id/quality_score）；④ Pipeline 注入顺序在 OpenAPI schema 可见。
- 依赖功能：F-001, F-009, F-010
- 冲突边界：与"不做记忆压缩"互斥（压缩算法在 Session 内部实现）。
- 关联问题：#6, #11
- 来源：[上游-问题6,11] + [v2计划-中间件层] + [S-011, S-013, S-016]

#### F-003 教学策略升级（费曼 + 遗忘曲线 + 阶段渐进 + 休息提醒 + 抗幻觉）
- 描述：把"AI 凭理解运行引擎"换成确定性流程引擎（**90% 状态机 + 10% LLM 兜底；兜底调用必带 trace_id + 输入/输出/评分写入审计日志 [S-019 采纳理由：71% 生产 Agent 故障位于 SDB 弱点，审计是生产可靠性基础]**）；6 大能力一一对应问题 12/13/10/16/18/20。
  - F-003.1 费曼学习法：每节学完生成"复述题"，让用户口述，引擎打分 + 追问薄弱点。
  - F-003.2 遗忘曲线：基于 **FSRS 调度算法（py-fsrs ≥ 0.16.0）[S-002 采纳理由：FSRS 已在 9,999 收藏集/3.5 亿次复习基准上对 99.6% 用户优于 SM-2，Anki 已采用]**，非自研；艾宾浩斯间隔重复，可视化显示曲线与下次复习时间。
  - F-003.3 阶段渐进：1.0→2.0 中插入 1.5"过渡档"，强度按用户最近 7 天正确率自适应。
  - F-003.4 休息提醒：连续学习 ≥ 25 分钟触发休息建议（区别于已有的"认知负荷过载"被动触发）。
  - F-003.5 抗幻觉：**嵌入方法仅作辅助过滤（假阳性高）；最终判定用 NLI 模型（DeBERTa-v3-large-mnli）或 LLM 法官（Grok-4-fast / Claude-haiku 评分，GPT-4 法官 7% 假阳性）；重检索循环 ≤ 2~3 次 + 提前退出 [S-012 采纳理由：HaluEval 嵌入假阳性 100%，NLI/LLM 法官多路径防御可降幻觉引用率 19.2%→3.1%]**。
  - F-003.6 流程引擎：用确定性状态机替代"AI 凭理解"，每步有输入/输出/可观测指标。
- 优先级：P0
- 用户角色：U1
- 验收标准：① BDD 场景 "学完一节后弹出费曼题" 通过；② 复习调度在 SQLite 中可查（FSRS 字段 = stability/difficulty/retrievability/next_due）；③ 25 分钟静默学习触发 toast；④ 事实性回答 100% 附带 source 引用，且 NLI/LLM 法官评分记录可查；⑤ 流程引擎状态转移图可在文档中复现。
- 依赖功能：F-002, F-009
- 冲突边界：与"不做个性化推荐"互斥。
- 关联问题：#2, #10, #12, #13, #16, #18, #20
- 来源：[上游-问题2,10,12,13,16,18,20] + [v2计划-教学策略升级] + [S-002, S-012, S-019]

#### F-004 数据管线（采集 + 清洗 + 中文 PDF + 本地优先 + 格式规范化）
- 描述：封装 4 步管线 Step1 采集（research-tool 10 源）、Step2 清洗（**MinHash Jaccard 阈值 0.85 + LLM 相关性过滤保留率 70% [S-008 采纳理由：research-tool 6 模块验证，Clean 步骤可量化]**）、Step3 入库（PDF/中文/英文统一 schema）、Step4 治理（实体/关系抽取→知识图谱）。中文 PDF 走 pdf2zh，并发翻译。

- 验收标准：① 1 份中文 PDF 入库后 `documents` 表有规范记录；② 同一 PDF 多次入库去重命中；③ `documents` 表 chunks 数量与原文段落数偏差 ≤ 5%；④ 本地资料路径优先级高于在线搜索（配置项可调）。
- 依赖功能：F-006, F-007, F-008
- 冲突边界：与"不做 OCR（图片型 PDF）"互斥——本期只处理文本型 PDF。
- 关联问题：#1, #14, #17
- 来源：[上游-问题1,14,17] + [v2计划-数据管线] + [S-008]

#### F-008 Agentic RAG + 重检索
- 描述：实现"检索→评估→补充→重检索"循环；评估指标 = 召回率预估 + 关键词命中率。考试要求 50% 资料覆盖时，未达阈值自动进入重检索；目标从 35% 提升到 70%+。**复杂度路由：仅 20~30% 查询走代理路径，其余走标准 RAG [S-003 采纳理由：80% 场景标准 RAG 即可，复杂查询走代理 RAG 是 LlamaIndex Agentic RAG 共识]**。
- 优先级：P1
- 用户角色：U1, U2
- 验收标准：① BDD 场景"覆盖不足 50% 时自动重检索"通过；② 重检索最多 3 轮，超出报错给用户；③ **复杂度路由分流（80% 标准 RAG / 20~30% 代理 RAG）**；④ 最终覆盖度 ≥ 70%（用户设定阈值）。
- 依赖功能：F-002, F-004, F-006
- 冲突边界：与"不做语义级去重"互斥（仅做关键词级）。
- 关联问题：#9, #15
- 来源：[上游-问题9,15] + [v2计划-AgenticRAG] + [S-003]

#### F-009 检索/精排/缓存/监控后端实现
- 描述：把问题 11 的"用户→预处理→检索→精排→LLM→后处理→回答"主链路实现，缓存层用 **SQLite+Redis 双后端（默认 SQLite，启用生产模式时切 Redis；语义阈值 0.85~0.95 [S-013 采纳理由：Redis 亚毫秒延迟 + 1200+ QPS 适合生产，SQLite 零基础设施适合本地]）**，监控层用 **structlog + OpenTelemetry Bridge [S-016]**。
- 优先级：P1
- 用户角色：U1, U4
- 验收标准：① 同一 query 二次请求 latency 下降 ≥ 50%；② 监控 API 返回字段 = `query/ts/cache_hit/llm_tokens/quality_score/trace_id/span_id`。
- 依赖功能：F-002
- 关联问题：#11
- 来源：[上游-问题11] + [S-013, S-016]

#### F-010 会话与长期记忆
- 描述：会话摘要自动生成（每 20 轮触发一次）、多会话切换、会话导出/导入、跨会话实体记忆。**短期记忆 = ConversationSummaryBufferMemory（早期摘要+近期原文）；长期记忆 = LangGraph Store + JSON 持久化；跨会话实体 = SQLite entities 表 + sqlite-vec 向量索引 [S-011 采纳理由：Hindsight 91.4% LongMemEval，LangGraph Store 标准化 + sqlite-vec 轻量向量]**。
- 优先级：P1
- 用户角色：U1
- 验收标准：① 会话 50 轮后 token 增长 < 30%（基线：无摘要时增长 ~ 200%）；② 切换会话响应 ≤ 500ms；③ 会话导出为 JSON 可再导入；④ 长期记忆的实体可被 RAG 检索命中。
- 依赖功能：F-002
- 关联问题：#6
