## 1. 需求背景与目标

### 1.1 背景
[上游] 当前 ai-tutor 形态为 4 个 MCP server（knowledge / tutoring / digest / sync）+ Claude Desktop 宿主。21 个测试发现问题（详见 `doc/发现问题.txt`）已系统性暴露 MCP 架构的瓶颈：MCP 调用不可靠、状态割裂、文件结构混乱、缺乏会话/缓存/监控层、缺乏长期记忆、AI 仅凭"理解"执行引擎而无确定性流程。
[上游] 用户原话（2026-06-02 复述）："我打算进行重构，变成一个软件，而不是 mcp，同时解决这些问题；注意开发请严格按照 c:\Users\yhn\Desktop\开发规范。"

### 1.2 核心目标
1. **G1（架构目标）** 把 ai-tutor 从"MCP 工具集"重构为"独立可分发软件"——单体后端 + 多端前端（桌面 / Web 可选 / CLI），消除对 Claude Desktop 宿主的强依赖。竞品演进路线参考（**V3.0 显式引述**）：LiteLLM（保留 MCP 作客户端 SDK）/ Aider（完全替换 MCP）/ Continue（同 Aider）/ Cline（异步 Tasks 标准化）——本项目走"服务端禁 MCP + 客户端 SDK 可演进"路线。[上游-21问题] + [V3.0-RI-001]
2. **G2（问题清零目标）** 21 个发现问题 100% 映射到可追溯的功能点，且每个问题至少有 1 条对应的验收标准。[上游-doc/发现问题.txt]
3. **G3（规范合规目标）** 严格遵循 `开发规范/conventions/`（01-架构 / 02-代码 / 03-Git / 04-API / 05-测试 / 06-文档 / 08-图谱）+ ai-workflow 7 篇流程。**V3.0 强化项**：把"规范红线覆盖度"作为 NFR-8 必达项（4 层工具链：Ruff + Import Linter + Redocly CLI + pre-commit + CI；详见 RI-004）。[上游-开发规范] + [V3.0-RI-004]
4. **G4（可分发目标）** 提供 CLI 入口、可选 GUI（**GUI 形态三选一，详见 OC-1 [S-017] 决策项**）、可选 Web；同时保留 Python 库形态供二次开发。**V3.0 显式引述**四形态方案：① pyproject + uv（库 + CLI 标准路径）② CLI 走 cx_Freeze onedir 或 Nuitka（禁 PyInstaller onefile）③ GUI 走 Electron / Tauri / PyWebView 三选一 ④ Web 走 FastAPI + Vite。[PM推断:依据=用户原话"变成一个软件"+ V3.0-RI-003]
5. **G5（学习能力目标）** 内置费曼学习法、遗忘曲线（**FSRS 算法 [S-002]**）、Agentic RAG（**含复杂度路由 [S-003]**）、缓存/监控/重检索、阶段渐进式过渡、**抗幻觉用 NLI/LLM 法官 [S-012]**，48 小时学完一科的核心承诺保持。**V3.0 显式引述**领域现状：FSRS 9,999 收藏集基准 / Anki 已采用 / LlamaIndex Agentic RAG / Self-RAG / Curio + LearnLM 范式。[上游-问题 9,12,13,15,16,18] + [V3.0-RI-002]

### 1.3 成功指标（**V3.0 微调**：S3 加入"开发规范 6+1 全部 0 红"）
