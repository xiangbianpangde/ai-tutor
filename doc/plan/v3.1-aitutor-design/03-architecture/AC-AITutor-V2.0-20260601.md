# 方案对比报告 — AITutor V2.0

> 主方案 vs 备选方案
> 7 维度评分（[SA:4.11]）

---

## 主方案 A：分层架构 + 局部插件化

### 模块划分
10 模块（M-001~M-010），L1 基础设施 → L6 表现层单向依赖；GUI 形态与 CLI 插件以适配器形式位于 L1。

### 模式约束
- 层间单向，禁止反向调用（[BR-039]）
- 5 类中间件强制装配（[BR-003]）
- 0 循环依赖（[BR-039]）

## 备选方案 B：微服务架构（拆分 4 进程）

### 模块划分
拆分为 4 进程：
- 进程1：教学引擎（M-002/M-008）
- 进程2：数据管线 + RAG（M-004/M-005）
- 进程3：会话记忆（M-006）
- 进程4：抗幻觉 + LLM 网关（M-003/M-007）
- M-001/M-009/M-010 跨进程共享

### 模式约束
- 进程间通过 gRPC/HTTP 通信
- 各进程独立 SQLite 实例（共享文件需协调）
- 引入消息队列（Redis Streams 或 NATS）

## 选择理由

**主方案 A 优于备选方案 B 19 分（> 5 分阈值）**：

1. **本期单用户场景**（[AR-006]）无需水平扩展，单进程性能足够
2. **强一致性要求**（[BR-039]）下多进程共享 SQLite 会引入分布式事务复杂度
3. **开发资源有限**（3 人月 vs 8 人月）
4. **运维简单**：单机部署 vs 多节点编排
5. **演进路径灵活**：V-3 阶段如需多用户，可将 M-006 拆出（局部微服务化），不需整体重写

**方案 B 适用场景**（不选但记录）：若本期需要支持 100+ 并发用户或 V-3 多用户时，应启动局部微服务化（先拆 M-006 会话记忆，再拆 M-004/M-005 数据层）。
