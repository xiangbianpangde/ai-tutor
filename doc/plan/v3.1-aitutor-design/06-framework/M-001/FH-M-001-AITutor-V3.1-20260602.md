## [DD-M 洞察] 本轮注入 ≥ 1 条

### 洞察 1：5MW 延迟导入的循环依赖风险

**洞察类型**: 循环导入风险
**触发条件**: app_factory.py 延迟导入 5 个业务模块（session/cache/monitor/pipeline/rag）
**风险描述**: 如果任一业务模块在导入时反向依赖 aitutor.app_factory（例如在 lifespan 启动时导入 AppLauncher 类型），将产生循环导入

**建议措施**:
1. 在业务模块中禁止 `from aitutor.app_factory import ...` 顶部导入
2. 如需引用，使用 TYPE_CHECKING 守卫：
   ```python
   from typing import TYPE_CHECKING
   if TYPE_CHECKING:
       from aitutor.app_factory import AppLauncher
   ```
3. 在 Import Linter 合约中显式禁止（[DD-001:CS-001] Contract 1 适用）

**来源标注**: [DD-M推断:依据=Import Linter Contract 1/2 + 延迟导入最佳实践]

---

### 洞察 2：Singleton ConfigLoader 的多环境配置切换

**洞察类型**: 可扩展性
**触发条件**: 当前 ConfigLoader Singleton 单实例仅支持单一 config_path / env_file
**风险描述**: 未来若需要支持多环境（dev / staging / prod）配置切换，当前 Singleton 模式需重构

**建议措施**:
1. 短期：保留 Singleton 但支持 `reload()` 方法清空缓存并重新加载
2. 长期：考虑改用 Factory 模式 + LRU 缓存（key = env_name）
3. 当前 V3.1 范围：保持 Singleton 即可，标注为 V3.2 演进项

**来源标注**: [DD-M推断:依据=Singleton 局限 + V3.1 范围控制]

---

### 洞察 3：测试文件 13 用例 × 3 文件 = 39 用例可能超出 V3.1 范围

**洞察类型**: 范围控制
**触发条件**: M-001 标注测试策略为「13 用例」，但当前按 3 个生产文件拆分测试为 3 × 13 = 39 用例
**风险描述**: 与 [DD-001:MD-001] 标注的 13 用例总量不一致

**建议措施**:
1. 选项 A：每个测试文件 13 用例（13 + 13 + 13 = 39 总用例，覆盖更深）
2. 选项 B：分配 13 用例到 3 文件（核心 5 + 边界 5 + 异常 3 = 13，3 文件共享）
3. 当前选择：选项 A，更细粒度测试覆盖，单文件 13 用例
