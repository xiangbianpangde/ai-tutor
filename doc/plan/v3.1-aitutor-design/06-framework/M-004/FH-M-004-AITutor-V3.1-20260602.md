## DD-M 洞察清单（5 条）

1. **跨模块依赖注释形式声明**（FDR-004）：M-004 对 M-017 storage / M-006 monitor 的依赖仅以类型注解 + 注释形式存在，下游 DD-S 实现阶段方实际 import — 严守 D7=100
2. **状态机表可注入设计**（FDR-002）：TRANSITIONS 模块级常量 + 构造时可覆盖，便于单测热替换 — 提升测试可行性
3. **DB 重试策略封装**（FDR-003）：`_execute_with_retry` 私有方法统一 OperationalError 处理，coro_factory 模式避免提前 await — 减少代码重复 + 符合 EX-011
4. **测试 fixture 集中管理**（FDR-005）：conftest.py 集中共享 fixture（async_engine、repository、service、sample_*），4 个 test_*.py 仅含 test 函数 — 符合 pytest 最佳实践
5. **timeout 双重路径**（DD-M 推断）：ACTIVE→EXPIRED（30min）与 SUSPENDED→EXPIRED（7d）触发事件同名"timeout"，实际由 service 层 cron 区分 — 状态机表只描述 (from, event) 对应关系，时长判断在 service 层
