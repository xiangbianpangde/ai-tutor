## DD-M 洞察注入

### [DD-M洞察-M009-001] 跨模块依赖委托的潜在 mock 复杂度

- **类型**：实现风险预判
- **描述**：M-009 通过 ActionDispatcher 委托 M-010/M-011/M-012，test_orchestrator.py 需 mock 3 个跨模块 handler；测试夹具可能膨胀至 5+ MagicMock 参数
- **缓解建议**：
  1. 在 tests/conftest.py 提供 `mock_teaching_handlers` 工厂 fixture
  2. 或在 dispatcher 层提供 testing-only 注册表（`register_for_test()`），避免生产代码与测试代码耦合
- **影响范围**：tests/unit/test_teaching/test_orchestrator.py、test_dispatcher.py
- **来源标注**：[DD-M推断:依据=Mediator+FSM 组合模式的测试隔离最佳实践]

### [DD-M洞察-M009-002] FSM 转换表 JSON 化的潜在反序列化风险

- **类型**：设计腐化预警
- **描述**：state_machine.py 中 transitions 默认值为 JSON 字符串 dict，Pydantic BaseModel 在运行期会触发 JSON 解析/校验；高频 next_step 调用可能引入性能抖动
- **缓解建议**：
  1. 启动期冻结转换表（frozenset/tuple），运行期只读
  2. 或在 __init__ 显式构造一次，避免 BaseModel 每次解析
- **影响范围**：state_machine.py、orchestrator.py（高频 next_step 调用方）
- **来源标注**：[DD-M推断:依据=Pydantic BaseModel 性能特性]

### [DD-M洞察-M009-003] Mediator fallback 缺审计可能导致 LLM 兜底静默

- **类型**：异常处理盲点
- **描述**：dispatch 未匹配 action 时走 fallback（LLM 兜底），但未强制写 audit_log；V3.1 SOP-009 要求所有 fallback 必写日志
- **缓解建议**：
  1. ActionDispatcher.dispatch 在 fallback 路径强制 publish_event("TEACHING_FALLBACK", {...})
  2. 配合 M-006 事件总线统一落 audit_log
- **影响范围**：dispatcher.py、monitor/bus.py（M-006 协同）
- **来源标注**：[DD-M推断:依据=EX-009/EX-006 异常处理规范]
