## 一、关系总览

```
V2 (ai-tutor 现有计划)           V3.1 (plan-writing 工作流产出)
11 功能点 + 10 份 design/ 文档  ←→  17 模块 + 100+ 份设计文档
                                 ↓
                          不是替代关系
                          是细化升级 + 局部重整
```

**核心判断**（建议）：
- v2 11 功能点 是 v3.1 17 模块的**子集超集**（v3.1 包含 v2 全部意图，但拆得更细）
- v3.1 引入 3 个 v2 没有的新关注点：① **打包调度**（M-015）② **红线编排**（M-016）③ **事件总线**（M-006）
- v3.1 合并了 v2 的两个前端点：可视化（#5）+ 客户端入口（M-003）整合

## 三、V3.1 相对 V2 的关键差异

### 3.1 新增模块（v2 没有，v3.1 引入）
| 模块 | 设计意图 | 为什么 v2 缺失 |
|---|---|---|
| **M-006 事件总线** | 模块间解耦通信 | v2 假设同步调用，没考虑模块爆炸后的耦合 |
| **M-015 打包调度** | Electron + Python 嵌入的异步打包任务调度 | v2 假设打包是单次命令，没考虑 CI/CD 场景 |
| **M-016 红线编排** | 5 条硬规则 BR-046~050 + 5 个红线专项异常 EX-021/029~033 | v2 缺失规范红线显式落地点（DEVELOPMENT-NORM + 开发规范均未映射）|

### 3.2 拆得更细的模块（v2 → v3.1）
- **#3 中间件层**：v2 1 个 → v3.1 3 个（Session + Cache + 事件总线）
- **#10 策略升级**：v2 1 个 → v3.1 6 个（教学编排 / 费曼 / FSRS / 阶段校准 / 长期记忆 / 红线）
  - 价值：v3.1 把 7 个教学策略（reduction/jiangjie/feynman/socratic/pbl/analogy/spaced_repetition）拆成可独立实施的子模块

### 3.3 合并的模块（v2 → v3.1）
- **#5 可视化 + #4 前端骨架** → M-003 客户端入口
- **#8 pdf2zh + #6 数据管线** → M-014 数据管线
- **#7 research-tool + #9 Agentic RAG** → M-007 Pipeline 调度 + M-008 RAG 引擎

### 3.4 技术栈升级（v2 没说清 / v3.1 明确）
| 维度 | v2 现状 | v3.1 升级 |
|---|---|---|
| 后端框架 | FastAPI | FastAPI 0.115（具体版本锁定）|
| Python | 3.11+ | Python 3.11（明确）|
| 包管理 | uv（隐含）| uv（明确 + uv.lock 锁版本）|
| RAG 编排 | 无明确方案 | LangGraph 1.0 StateGraph |
| 抗幻觉 | 无 | **HaluGate 三级级联**（DeBERTa NLI → Haiku → GPT-4）|
| 缓存 | 概念级 | sqlite-vec + Redis 双后端 |
| LLM 抽象 | providers/ | LiteLLM 风格统一接口 |

- **M-001 + M-002 + M-003**（对应 v2 #1 + #2 + #4）→ 后端骨架 + API 网关 + 前端入口
- 触发条件：v2 #1 + #2 + #4 任何一个先开始

- **M-008 + M-009**（对应 v2 #9 + #10 部分）
- 触发条件：v2 #9 启动后

- 触发条件：v2 #10 启动后

- 触发条件：v2 #11 启动后

## 五、决策建议（给开发 agent / 用户）

| 选项 | 适合场景 | 工作量 |
|---|---|---|
| **A. 按 v2 11 功能点推进** | 时间紧 / 沿用已有 v2 设计文档 | 0 额外（直接按 v2 现有节奏）|
| **B. 按 v3.1 17 模块推进** | 想用 v3.1 的细化方案 | 需把 17 模块映射回 v2 11 功能点（用本表）|
| **C. v2 推进 + v3.1 增量替代** | v2 主体 + v3.1 引入的新模块（红线/打包/事件总线）| 推荐，渐进式升级 |
| **D. v3.1 全面替代 v2** | 大重构 | 工作量大，需要重新设计 v2 10 份 design/ 文档 |

**推荐 C**——v2 主体不动（已审查稳定），v3.1 引入的 3 个新模块（事件总线/打包调度/红线编排）作为增量补充，v2 #10 策略升级按 v3.1 6 模块拆分细化。
