### 1.2 关键设计洞察（DD 主动发现，4.6 机制）

#### [DD洞察-001] M-008 RAG 子能力内聚度过低
- **类型**：设计模式误用 + 模块内聚风险
- **描述**：M-008 当前承担 RAG 路由 + NLI + 本地索引 + 翻译 4 大子能力，TD-AR-005 记录内聚度 3/6（最低）
- **缓解**：本设计采用子能力命名空间隔离（`m008.routing` / `m008.nli` / `m008.indexing` / `m008.translation`），通过接口隔离副作用；V3.2 触发 100 用户时物理拆分
- **来源**：[TD-AR-005] + [AR:AC-AITutor:TD-AR-005]

#### [DD洞察-002] PDF 翻译 + NLI 推理存在 CPU 争抢
- **类型**：性能瓶颈预判
- **描述**：M-014 PDF 翻译（512MB+ThreadPool）与 M-008 NLI（1.5GB+transformers）在同一 CPU 池中并发，4 核下可能争抢
- **缓解**：M-001 启动期绑定 NLI 到 CPU 0 亲和性；M-014 PDF 翻译走 ThreadPool 走 CPU 1-3（来源 AR 洞察 INSIGHT-AR-001）
- **来源**：[AC:INSIGHT-AR-001] + [AR推断:依据=asyncio GIL+多线程调度]

#### [DD洞察-003] 长期记忆 LRU 误删风险
- **类型**：技术债务 + 异常处理
- **描述**：M-013 LRU 淘汰最旧 10% 可能误删关键事实；当前未实现重要性评分
- **缓解**：EX-013 异常处理策略——淘汰前 audit_log 记录「拟淘汰列表」+ 用户可读 markdown 导出；V4.5 引入「重要性 × 时间衰减」评分
- **来源**：[TD-AR-006] + [AR推断:依据=LRU 策略与用户期望冲突]

#### [DD洞察-004] WS 重连风暴下事件总线压力
- **类型**：并发安全 + 异常处理
- **描述**：max_connections=1000 + 状态补发 30s 内 + 心跳 5s；1000 个断连同时重连将导致事件总线堵塞
- **缓解**：指数退避（base=1s，max=30s，jitter±30%）+ 连接级别优先级队列；超 800 触发 E00202 软拒绝
- **来源**：[API-008 限流] + [AR推断:依据=雷鸣群 herd effect]

#### [DD洞察-005] 4 工具链 Ruff 1.0 升级窗口
- **类型**：技术债务
- **描述**：Ruff 1.0 前 API 破坏性变更（REDOC-09）；DE-048 锁版本缓解
- **缓解**：CS-NNN 风格指南固化为 .ruff.toml 全规则集；CI 锁版本不升级；V3.2 走 TDD 渐进式（先 5% 规则 → 全量）
- **来源**：[TD-AR-004] + [调研报告:REDOC-09]

**阶梯退出检查**：①全部 M 已分类: 是 ②全部 API 已分类: 是 ③D1: 100%

## 二、设计模式选择与多方案对比（L1/D2+T3+T4 产出）

### 2.1 选定设计模式

**主方案（A）**：「分层 + 插件化 + 事件总线 + Repository + Pipeline + FSM + 策略 + 观察者」组合模式
- **选择理由**：AR 已在 TDR-001/002 锁定混合架构（分层核心 + 插件化注入可替换引擎 + 事件总线解耦），DD 继承并向下细化为 8 大模式组合
- **模式约束**：
  - Repository 模式：每个实体对应一个 Repository 类（`repositories/` 目录）
  - 策略模式：策略接口统一签名（`strategies/` 目录）
  - 状态机模式：状态转换必须完整 + 终止条件（`states/` 目录）
  - 适配器模式：LLM/NLI/PDF 三个外部能力用适配器封装
  - 事件总线模式：trace_id 32hex 全埋点 + 解耦 WS 推送

**备选方案（B）**：「单体函数式 + 全局状态 + 同步执行」反模式
- 备选方案特征：无模式约束 + 全局 dict + 同步阻塞
- 拒绝理由：违背 BR-002 单进程 asyncio + BR-007 WS≤1s + BR-009 90% FSM 强制需求；模块耦合度爆炸，测试不可行
