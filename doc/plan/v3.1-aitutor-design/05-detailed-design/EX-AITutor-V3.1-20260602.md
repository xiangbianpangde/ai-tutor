## EX-001 启动期异常（SEC-001/002 启动期）

- **关联边界**：SEC-001 CLI / SEC-002 Web 启动期
- **异常类型**：系统异常
- **触发条件**：5MW 任一未注册 / 端口冲突 / 旧库不兼容 / 配置文件缺失
- **处理流程**：
  - 步骤 1：检测异常（启动期 validate）
  - 步骤 2：详细记录日志（structlog ERROR 级别 + trace_id）
  - 步骤 3：拒绝启动（退出码非 0）
  - 步骤 4：友好提示用户（错误码 + 修复手册链接）
- **降级策略**：N/A（启动期无降级，必须成功）
- **告警机制**：级别 ERROR / 方式：日志+退出码 / 对象：用户+CI
- **错误码**：E00101（依赖缺失）/ E00102（端口冲突）/ E00103（旧库不兼容）/ E00106（MW 失败）
- **来源标注**：[AR:API-001] + [AR:SEC-001/002]

## EX-002 WS 断连风暴（SEC-007）

- **关联边界**：SEC-007 WebSocket 推送输出
- **异常类型**：网络异常
- **触发条件**：max_connections > 1000 / 客户端异常重连（herd effect）
- **处理流程**：
  - 步骤 1：检测异常（连接数监控 + 重连频率）
  - 步骤 2：记录日志（trace_id + 连接数 + 重连次数）
  - 步骤 3：触发 E00202 软拒绝（800~1000 区间）
  - 步骤 4：客户端指数退避（base=1s, max=30s, jitter±30%）
- **降级策略**：客户端降级轮询（HTTP fallback）
- **告警机制**：级别 WARN（>800）/ ERROR（>1000）/ 方式：Prom 指标 + 日志 / 对象：监控
- **错误码**：E00201（连接断开）/ E00202（超限拒绝）
- **来源标注**：[AR:API-008] + [DD推断:依据=雷鸣群 herd effect 防护]

## EX-003 LLM Provider 超时（SEC-003）

- **关联边界**：SEC-003 LLM Provider 接口
- **异常类型**：网络异常
- **触发条件**：httpx 调用 30s 未响应 / 连接失败 / API key 失效
- **处理流程**：
  - 步骤 1：检测异常（httpx.TimeoutException / HTTPStatusError）
  - 步骤 2：记录日志（trace_id + provider + 错误码）
  - 步骤 3：重试 1 次（指数退避 2s）
  - 步骤 4：仍失败走 LLM 兜底 10%（[AR:PO-005]）→ 标"无法确认"（Pipeline 阶段）
- **降级策略**：LLM 兜底 10% / 切到本地 LLM（Ollama）
- **告警机制**：级别 WARN（重试）/ ERROR（兜底）/ 方式：Prom 指标 / 对象：监控
- **错误码**：E00706（LLM 超时）/ E00802（NLI 不可用时也走兜底）
- **来源标注**：[AR:SEC-003] + [AR:PO-005]
