## DDR-001 详细设计模式：8 大模式组合

- **决策状态**：已接受
- **决策内容**：采用「分层 + 插件化 + 事件总线 + Repository + Pipeline + FSM + 策略 + 观察者」8 大模式组合
- **决策理由**：
  - [AR:TDR-001/002] 锁定混合架构（分层核心 + 插件化注入可替换引擎 + 事件总线解耦）
  - Repository 模式屏蔽 DB 差异（SQLite/Redis/Chroma）
  - Pipeline 模式实现 5 阶段管线
  - FSM 满足 BR-009/010（90% FSM + 10% LLM 兜底）
  - 策略模式封装 NLI/PDF/翻译多个可替换引擎
  - 观察者模式实现 trace/事件总线
- **拒绝的替代方案**：
  - 单体函数式：无模式约束 + 全局状态 + 同步阻塞 → 违背 BR-002 asyncio + BR-007 WS≤1s
  - 纯微服务：违背 BR-002 单进程
  - 纯插件化：核心不稳定
- **影响范围**：M-001~M-017 全部 17 模块
- **相关DDR**：DDR-002、DDR-003、DDR-004
- **来源标注**：[AR:TDR-002] + [DD推断:依据=AR 已锁定架构]

## DDR-002 M-008 子能力命名空间隔离

- **决策状态**：已接受
- **决策内容**：M-008 RAG 引擎采用子能力命名空间隔离（`m008.routing` / `m008.nli` / `m008.indexing` / `m008.translation`），不进行物理拆分
- **决策理由**：
  - [AR:TD-AR-005] 当前内聚度 3/6（最低）已记录 V3.2 拆分
  - V3.1 单用户场景下子能力命名空间隔离可有效管理副作用
  - V3.2 触发条件 100 用户时物理拆分
  - 4 工具链（Import Linter）通过 `independence` contract 强制隔离
- **拒绝的替代方案**：
  - 即时物理拆分：违背 YAGNI + 增加部署复杂度
  - 不做隔离：内聚度爆炸，修改影响面失控
- **影响范围**：M-008 RAG 引擎、M-014 数据管线（翻译子能力）
- **相关DDR**：DDR-001
- **来源标注**：[AR:TD-AR-005] + [DD推断:依据=AR 洞察 INSIGHT-AR-001 衍生]

## DDR-003 并发控制：asyncio + WAL + Semaphore 三重保护

- **决策状态**：已接受
- **决策内容**：所有并发写操作采用「asyncio.Lock（协程级）+ SQLite WAL（数据库级）+ asyncio.Semaphore（业务级）」三重保护
- **决策理由**：
  - [AR:BR-002] 单进程 asyncio
  - [AR:TS-003] SQLite WAL 模式可支撑 100+ 并发读
  - IC-002 学习回合要求并发安全 + 幂等
  - EX-024 并发写冲突需自动重试
- **拒绝的替代方案**：
  - 全局锁：阻塞所有写，违反 BR-007 WS≤1s
  - 乐观锁：SQLite 单进程下 WAL 已足够
  - 多进程：违背 BR-002
- **影响范围**：M-004 Session、M-013 Memory、M-014 Ingest、M-017 Storage
- **相关DDR**：DDR-001
- **来源标注**：[AR:API-002 并发安全] + [AR:EX-024] + [DD推断:依据=Python asyncio 最佳实践]

## DDR-004 文件组织：src layout + 子能力命名空间

- **决策状态**：已接受
- **决策内容**：采用 Python src layout（`src/aitutor/`），每个业务模块一个子包，子能力深一层命名空间
- **决策理由**：
  - Python 官方推荐 src layout（避免 import path 冲突）
  - 4 工具链（Import Linter）支持精细化层级约束
  - 子能力命名空间（如 `aitutor.rag.nli`）配合 Import Linter independence contract 隔离
  - 测试 `tests/unit/test_<module>/` 镜像结构
- **拒绝的替代方案**：
  - flat layout（根目录 `aitutor/`）：test 与 prod 路径冲突
  - 单层命名空间：M-008 子能力隔离困难
- **影响范围**：全部 17 模块 + tests
- **相关DDR**：DDR-002
- **来源标注**：[AR:CS-NNN src layout] + [DD推断:依据=Python 最佳实践]

## DDR-006 接口契约验收：4.12 6 项强制

- **决策状态**：已接受
- **决策内容**：所有 IC 必须通过 4.12 验收（入参完整/出参完整/错误码覆盖/时序明确/前置后置/幂等性定义），8/8 全部通过
- **决策理由**：
  - [AR:API-001~008] 8 IF 全有完整规范
  - 4.12 验收标准是 DD 第⑥阶段硬性约束
  - 缺幂等性会导致重复请求副作用
  - 缺时序会导致异步接口回调混乱
- **拒绝的替代方案**：
  - 简化 IC 定义：开发期歧义多
  - 不定义幂等性：API 重试引发数据不一致
- **影响范围**：8 IF × 6 项验收 = 48 项检查全通过
- **相关DDR**：DDR-005
- **来源标注**：[AR:IC-001~008] + [DD推断:依据=soul 4.12 验收清单]

## DDR-007 异常处理：15 边界 + 9 场景 + 24 EX

- **决策状态**：已接受
- **决策内容**：15 边界（SEC-001~015）全有 EX 处理策略 + 9 异常场景（启动/WS/LLM/NLI/缓存/PDF/审计/限流/FSM）单独覆盖，共 24 条 EX
- **决策理由**：
  - [AR:SEC-001~015] 15 边界 100% 覆盖
  - [AR:PO-001~010] 10 性能指标全有兜底

- **拒绝的替代方案**：
  - 仅处理 P0 边界：边缘 case 频发
  - 缺失降级：单点失败全局崩溃
- **影响范围**：M-001~M-017 + 4 工具链 + 部署
- **相关DDR**：DDR-008
- **来源标注**：[AR:SEC-001~015] + [AR:PO-001~010] + [DD推断:依据=异常场景完整性]

## DDR-008 腐化检测：6 项全监控

- **决策状态**：已接受
- **决策内容**：建立 4.14 6 项腐化指标监控（设计模式过时/接口契约膨胀/数据结构冗余/文件结构混乱/异常处理失效/可追溯性丢失），V3.2 引入自动化检查
- **决策理由**：
  - 4.14 是 DD 第⑥阶段硬性约束
  - V3.1 → V3.2 → V4.0 演进过程中详细设计可能腐化
  - 当前 0 项触发，但需建立监控机制
  - 未来触发时按 1-2/3-4/≥5 三级处理
- **拒绝的替代方案**：
  - 无监控：腐化累积到 V4.0 重构
  - 全自动重构：风险不可控
- **影响范围**：V3.2+ 全周期
- **相关DDR**：DDR-001~007
- **来源标注**：[DD推断:依据=soul 4.14 腐化检测]
