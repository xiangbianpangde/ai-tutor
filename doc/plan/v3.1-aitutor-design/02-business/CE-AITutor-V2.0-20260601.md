## CE-001 [核心] 旧库迁移循环依赖
- **关联流程**：BP-001
- **失效场景**：用户从 v1 升级到 v2，旧 `tutor.db` 缺 `fsrs_cards` 表（v1 没有），但 v2 的所有会话查询都引用该表 → 启动后所有会话功能崩溃
- **根因**：F-001 验收② "旧库兼容" 仅测试 v1 schema，但 v1 没 FSRS（v2 新增），启动时未做"缺表"检查
- **影响范围**：BP-015 全部失效；F-010 不可用
- **当前处理能力**：不能——EX-001 仅做 schema 字段级迁移，未做表级
- **建议修复**：在 BP-001 步骤 3 增加"缺表自动 CREATE TABLE"步骤；新增迁移脚本 `migrate_v1_add_fsrs.py`

## CE-002 [核心] Redis 雪崩
- **关联流程**：BP-002
- **失效场景**：Redis 缓存大量 key 同时过期（TTL 相同），请求瞬间穿透到 SQLite + LLM → 雪崩
- **根因**：BR-005 缓存语义阈值已设，但未设过期时间抖动
- **影响范围**：所有查询变慢；成本激增
- **当前处理能力**：部分——EX-005 降级到 SQLite 可承受，但不能阻止雪崩
- **建议修复**：在 DE-007 `expires_at` 生成时加 ±20% 随机抖动；监控埋点加 `cache_eviction` 事件

## CE-003 [核心] 费曼题评分串号
- **关联流程**：BP-003
- **失效场景**：用户 A 提交费曼题回答，LLM 评分结果错误地写入了用户 B 的 profile
- **根因**：DE-013 / DE-014 实体无 `user_id` 强校验，状态机评分时按 `question_id` 查表 → race condition
- **影响范围**：用户学习数据错乱；合规风险
- **当前处理能力**：不能——EX-009/010 未覆盖此类
- **建议修复**：DE-013 必填 `user_id`；评分时按 `answer_id + user_id` 双键校验

## CE-004 [核心] FSRS 评分=Again 风暴
- **关联流程**：BP-004
- **失效场景**：用户对同一张卡片连续点击 "Again" 多次，FSRS 把 stability 重置到初始值 → 卡片瞬间堆积 100+ 张待复习
- **根因**：BR-012 字段规则已定，但 BP-004 步骤 2 未限制"短时间内同一卡片的 Again 次数"
- **影响范围**：看板爆炸；用户体验差
- **当前处理能力**：部分——EX-012 仅做并发控制，无 Again 节流
- **建议修复**：BP-004 步骤 2 增加"同卡片 5 分钟内仅允许 1 次 Again"节流

## CE-005 [核心] 阶段档位跳变
- **关联流程**：BP-005
- **失效场景**：用户某天正确率刚好 79%（在 60-80 区间），下一天正确率 81% → 档位从 1.5 跳到 2.0；课程密度陡增
- **根因**：BR-014 阈值硬边界，缺少 hysteresis
- **影响范围**：用户被过度挑战
- **当前处理能力**：不能——无 hysteresis
- **建议修复**：BR-014 改为"升档需连续 2 天 >80%；降档需连续 2 天 <60%"，加滞后

## CE-006 [核心] 抗幻觉 NLI 全通过但实际有错
- **关联流程**：BP-007
- **失效场景**：HaluGate 第一层 NLI 100% 通过（DeBERTa FPR 100%），第二层 SLM 也未检出，第三层 LLM 法官 token 超限被跳过 → 最终回答无幻觉评分
- **根因**：调研报告 R-03 已警告 NLI 假阳性 100%；S-012 已要求多路径，但任一层失败时无强制 prompt retry
- **影响范围**：事实性回答可能错误（合规性受损）
- **当前处理能力**：部分——EX-015/016/017 覆盖单层失败，但缺强制 retry
- **建议修复**：BP-007 步骤 2/3/4 任一失败时强制重试 1 次；步骤 4 LLM 法官全部失败则阻断回答（"宁缺毋滥"）

## CE-007 [核心] 状态机版本漂移
- **关联流程**：BP-008
- **失效场景**：开发者更新状态机规则（DE-021 `version=2`），但用户本地 SQLite 仍是 v1 规则 → 用户行为触发"未定义状态"频繁走 LLM 兜底
- **根因**：DE-021 字段 `version` 已记录，但 BP-008 启动时未校验版本
- **影响范围**：成本激增；审计日志暴增
- **当前处理能力**：部分——EX-018 兜底连续触发可检测，但已发生后才能识别
- **建议修复**：BP-008 步骤 1 启动时校验 `state_machine.version` 与持久化的 `learner_profile` 匹配，不匹配则强制升级

## CE-008 [核心] 文档并发入库覆盖
- **关联流程**：BP-009
- **失效场景**：用户同时喂入两个相同 PDF（来自不同目录），并发执行 BP-009 → 后入库的覆盖先入库的元数据
- **根因**：DE-025 `doc_id` 唯一但无 UPSERT 保护
- **影响范围**：入库数据丢失；用户以为入库失败
- **当前处理能力**：不能——EX-021 仅做内容去重，不做并发保护
- **建议修复**：DE-025 加 `content_hash` 唯一约束；BP-009 步骤 3 用 `INSERT OR REPLACE` + WARN

## CE-009 [核心] WebSocket 心跳丢失导致看板假死
- **关联流程**：BP-010
- **失效场景**：用户长时间无操作（> 5 分钟），WS 心跳超时但前端未显示断连 → 看板看似实时但实际不更新
- **根因**：DE-005 `last_ping_at` 已记录，但前端未做心跳监控 UI
- **影响范围**：用户体验差
- **当前处理能力**：部分——EX-025 断连会重连，但心跳丢失期间用户无感知
- **建议修复**：前端看板增加"连接状态"指示器；> 3 分钟无 ping → 黄色"延迟"提示

## CE-010 [核心] 重检索循环 + 抗幻觉双重循环死锁
- **关联流程**：BP-013 + BP-007
- **失效场景**：RAG 重检索 3 轮后覆盖度 65%（< 70%）→ 触发 BP-007 抗幻觉 → 抗幻觉返回"重检索"建议 → 回到 BP-013 步骤 5 → 死循环
- **根因**：BP-013 与 BP-007 互相调用，无全局循环上限
- **影响范围**：请求超时；用户无法得到回答
- **当前处理能力**：不能——无全局上限
- **建议修复**：引入全局 `max_total_rounds=5` 计数器；任一循环超限强制返回"已尽力" + 降级回答

## CE-011 [核心] 缓存污染
- **关联流程**：BP-014
- **失效场景**：用户问敏感问题，得到 LLM 拒绝回答 → 该回答被写入缓存（cache_value="我无法回答..."）→ 第二次相似 query 直接返回拒绝 → 用户无法获取正常回答
- **根因**：BP-014 步骤 8 缓存写回未做"内容质量"过滤
- **影响范围**：缓存被错误回答污染
- **当前处理能力**：不能——EX-033 仅写失败处理
- **建议修复**：BP-014 步骤 6 后处理增加"拒绝回答不入缓存"判断；cache_value 含"无法/不能/拒绝"关键词则跳过写回

## CE-012 [核心] 长期记忆跨用户污染
- **关联流程**：BP-015
- **失效场景**：用户 A 切到用户 B 的 session，但 LangGraph Store 未做 user 隔离 → A 看到 B 的长期记忆
- **根因**：DE-035 字段 `user_id` 已记录，但 BP-015 步骤 3 加载时未按 user 过滤
- **影响范围**：隐私泄露（严重）
- **当前处理能力**：不能——EX-035/036 不涉及隔离
- **建议修复**：BP-015 步骤 3 强制 `WHERE user_id = current_user_id`；加 lint 检测

## CE-013 [核心] GUI 形态决策延迟导致打包失败
- **关联流程**：BP-016
- **失效场景**：PM 在打包前 1 天才决定 GUI 形态（如选 Tauri），但 Tauri 需要 Rust 工具链 + 重写 PDF 解析桥 → CI 三平台构建全失败
- **根因**：BR-037/BR-038 假设 GUI 已选；OC-1 决策延迟
- **影响范围**：发布延期
- **当前处理能力**：部分——EX-037/038 仅做体积/许可
- **建议修复**：BP-016 步骤 2 强制依赖 OC-1 决策 ID；如未决策则 build 流程不开始

## CE-014 [核心] STATUS.md 写入竞争
- **关联流程**：BP-018
- **触发**：两个任务几乎同时完成，都触发 STATUS.md 重写
- **根因**：BP-018 步骤 2 原子写（.tmp + rename）可避免损坏，但不保证顺序
- **影响范围**：STATUS.md 内容顺序错乱
- **当前处理能力**：不能——无任务级排序
- **建议修复**：步骤 2 加 `tasks` 表 `completed_at` 排序后再渲染

## CE-015 [标准] research-tool Backward 循环死循环
- **关联流程**：BP-011
- **触发**：质量评分持续 < 阈值，Backward 自动重试 → 质量评分仍 < 阈值 → 死循环
- **根因**：BR 未限制 Backward 轮次
- **影响范围**：CLI 卡死
- **建议修复**：在 BP-011 步骤 7 加 `max_backward_rounds=3` 强制退出

## CE-016 [标准] 本地资料路径含特殊字符
- **关联流程**：BP-019
- **触发**：用户配置 `local_sources` 路径含中文 + 空格 + emoji
- **根因**：DE-041 `path` 字段无规范化
- **影响范围**：路径解析失败
- **建议修复**：BP-019 步骤 1 规范化路径（urllib.parse / pathlib）；WARN 但继续

## CE-017 [辅助] Anki-Connect 端口冲突
- **关联流程**：BP-020-A
- **触发**：用户已开其他应用占用 8765 端口
- **根因**：EX-042 已处理"不可用"，但未处理"端口冲突"
- **建议修复**：Anki-Connect 配置项允许自定义端口

## CE-018 [辅助] Obsidian vault 包含 10000+ 文件
- **关联流程**：BP-020-B
- **触发**：用户已有大型 vault，新写笔记触发 Git 操作
- **根因**：EX-043 仅警告 100MB
- **建议修复**：扫描 vault 时跳过 .obsidian/ 内部状态；分批 commit

## CE-019 [核心] LLM 法官自恋偏差
- **关联流程**：BP-007
- **触发**：用 Claude Haiku 评 Claude 输出的回答 → 评分系统性偏高
- **根因**：调研报告 R-16 已识别
- **影响范围**：幻觉评分失真
- **建议修复**：BR-018 强制 ≥ 2 异构 LLM 法官；仲裁权重 = min(scores)

## CE-020 [核心] 缓存键碰撞
- **关联流程**：BP-002 / BP-014
- **触发**：两个不同 query 哈希碰撞（极小概率但发生过）
- **根因**：DE-007 `cache_key` 用 hash，未带语义向量
- **影响范围**：错误回答返回
- **建议修复**：cache_key 组合 = query_hash + semantic_embedding_top1_doc_id；命中后做二次校验
