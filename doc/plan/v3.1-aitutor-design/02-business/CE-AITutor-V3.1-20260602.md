## CE-001 [核心] 旧库迁移循环依赖
- **关联流程**：BP-001
- **失效场景**：v1 升级到 v2，旧 `tutor.db` 缺 `fsrs_cards` 表 → 启动后所有会话功能崩溃
- **根因**：F-001 验收②"旧库兼容"仅测试字段级，未做表级
- **影响范围**：BP-015 / F-010 不可用
- **当前处理能力**：不能——EX-001 仅字段级
- **建议修复**：BP-001 步骤 3 加"缺表自动 CREATE TABLE" + `migrate_v1_add_fsrs.py`
- **来源标注**：[反例验证:沿用 V2.0]

## CE-002 [核心] Redis 雪崩
- **关联流程**：BP-002, BP-012
- **失效场景**：Redis key 大量同时过期（TTL 相同）→ 雪崩
- **根因**：BR-005 阈值已设，但 expires_at 无抖动
- **影响范围**：查询变慢 + 成本激增
- **当前处理能力**：部分（EX-005 降级到 SQLite）
- **建议修复**：DE-007.expires_at 加 ±20% 抖动（BR-027）+ 监控 cache_eviction
- **来源标注**：[反例验证:沿用 V2.0]

## CE-003 [核心] 费曼题评分串号
- **关联流程**：BP-003
- **失效场景**：用户 A 提交费曼题 → 评分写入用户 B 的 profile
- **根因**：DE-013 缺 user_id 强校验
- **影响范围**：数据错乱 + 合规风险
- **当前处理能力**：不能（EX-009/010 未覆盖）
- **建议修复**：DE-013 必填 user_id + 评分按 (answer_id, user_id) 双键校验
- **来源标注**：[反例验证:沿用 V2.0]

## CE-004 [核心] FSRS Again 风暴
- **关联流程**：BP-004
- **失效场景**：同卡片 5 分钟内 Again 多次 → 稳定性重置 → 堆积 100+ 张
- **根因**：BR-012 字段规则已定，但 BP-004 步骤 2 无节流
- **影响范围**：看板爆炸
- **当前处理能力**：部分（EX-012 无 Again 节流）
- **建议修复**：BP-004 步骤 2 加"同卡片 5 分钟内仅 1 次 Again"节流 + DE-016 增 again_throttle_count 字段
- **来源标注**：[反例验证:沿用 V2.0]

## CE-005 [核心] 阶段档位跳变
- **关联流程**：BP-005
- **失效场景**：连续 2 天跨阈值 → 档位 1.5 跳 2.0
- **根因**：BR-013 硬边界无 hysteresis
- **影响范围**：用户被过度挑战
- **当前处理能力**：不能
- **建议修复**：BR-014 = 升档需连续 2 天 >80%；降档需连续 2 天 <60%（+ DE-018.consecutive_high_days）
- **来源标注**：[反例验证:沿用 V2.0]

## CE-006 [核心] 抗幻觉 NLI 全通过但实际有错
- **关联流程**：BP-007
- **失效场景**：NLI 评分全 ≥ 0.7，但答案含未引用但合理推断的事实
- **根因**：BR-017 阈值单一，无多模型交叉
- **影响范围**：用户被误导
- **当前处理能力**：部分（EX-015 NLI 不可用有兜底）
- **建议修复**：BR-017 升级为多模型交叉裁决 + 评分阈值校准（[R-16] 移交 SA-001 RI-NEW-1）
- **来源标注**：[反例验证:沿用 V2.0] + [调研报告:R-16]

## CE-007 [核心] 长期记忆数据孤岛
- **关联流程**：BP-013
- **失效场景**：长期记忆实体被多个流程引用但无创建/更新流程
- **根因**：DE-032 在 BR-028 规则中定义，但无专门 BP 负责创建
- **影响范围**：长期记忆实际为空
- **当前处理能力**：不能
- **建议修复**：BP-013 步骤 3 显式化为"关键事实提取"子流程（已有）+ 加监控埋点
- **来源标注**：[反例验证:沿用 V2.0] + [AR-017 备选]

## CE-008 [核心] 状态机兜底审计缺失
- **关联流程**：BP-008
- **失效场景**：LLM 兜底 10% 失败未审计
- **根因**：BR-009 / BR-010 规则已定，但 audit_log 表无强制非空约束
- **影响范围**：兜底失败无法追溯
- **当前处理能力**：不能
- **建议修复**：DE-024 字段全 NOT NULL + CI 检查 audit_log 行数 ≥ LLM 调用行数 × 10%
- **来源标注**：[反例验证:沿用 V2.0] + [调研报告:R-09/R-13]

## CE-009 [核心] PDF 翻译质量回退
- **关联流程**：BP-009
- **失效场景**：DeepSeek 成语翻译 28% 错误率（已观察）→ 用户体验差
- **根因**：BR-021 仅约束时间，未约束质量
- **影响范围**：中文论文翻译失真
- **当前处理能力**：部分（EX-018 3 次重试后切 LM Studio）
- **建议修复**：DE-025.quality_score 字段 + 阈值 < 4/5 时自动切换翻译模型
- **来源标注**：[反例验证:沿用 V2.0] + [调研报告:R-04]

## CE-010 [核心] 复杂度路由误判

- **失效场景**：路由把复杂查询误判为简单 → 单轮检索失败
- **根因**：BR-020 阈值未实测（RI-NEW-4 移交）
- **影响范围**：RAG 质量下降
- **当前处理能力**：部分（EX-021-2 重路由）
- **建议修复**：阈值上线后 A/B 测试 + 监控 fallback_rate
- **来源标注**：[反例验证:沿用 V2.0] + [RI-NEW-4 POC 移交]

## CE-011 [核心] 打包体积与覆盖率冲突
- **关联流程**：BP-014, BP-021
- **失效场景**：补覆盖率测试 → backend 体积上升 → 触发 EX-023 体积超目标
- **根因**：BR-045（覆盖率 ≥ 80%）与 BR-032（CLI < 50MB）无仲裁
- **影响范围**：GUI 产物 ❌
- **当前处理能力**：不能
- **建议修复**：BR-032 改为"warn only，不阻塞" + 优先 UPX 压缩
- **来源标注**：[反例验证:本轮 V3.1 新增 / 跨流程风险]

## CE-012 [核心] 【V3.1 新增】红线命令误报
- **关联流程**：BP-021
- **失效场景**：Ruff 升级到 1.0 前某天突然把 `print` 视为 WARN（实际是 INFO）→ CI 红 → PR 不可 merge
- **根因**：Ruff 1.0 前破坏性 API 变更
- **影响范围**：所有 PR 阻塞
- **当前处理能力**：能（BR-048 CI 锁版本已缓解）
- **建议修复**：维持 CI 锁版本（DE-048）+ 升级走 TDD 渐进式（先 staging 后 main）
- **来源标注**：[调研报告:R-17] + **V3.1:S-021 缓解**

## CE-013 [核心] 【V3.1 新增】Import Linter 合约误配置
- **关联流程**：BP-021 步骤 1
- **失效场景**：`.importlinter` 中 `forbidden` 列表写错（如把 `domain` 层错配为可被 `framework` 调用）→ 所有 backend 模块红
- **根因**：合约配置无人 review
- **影响范围**：CI 永远红
- **当前处理能力**：部分（修复手册有，但需手动查合约）
- **建议修复**：BP-021 步骤 1 跑前先校验 `.importlinter` 语法（`import-linter check-config`）+ 合约变更走 PR 强制 2 approver
- **来源标注**：[反例验证:本轮 V3.1 新增]

## CE-014 [核心] 【V3.1 新增】Redocly 规则集过严阻塞
- **关联流程**：BP-021 步骤 4
- **失效场景**：`--extends=recommended-strict` 规则集中某条新规则（如 `info-license-url`）→ 所有 API 端点缺 license URL → 全红
- **根因**：规则集自动升级
- **影响范围**：所有 API 变更阻塞
- **当前处理能力**：能（CI 锁版本）
- **建议修复**：维持锁版本 + 规则集升级走单独 PR（先文档化影响）
- **来源标注**：[反例验证:本轮 V3.1 新增] + [调研报告:R-06]

## CE-015 [核心] 【V3.1 新增】S3 测量三层矛盾
- **关联流程**：BP-021 步骤 9
- **失效场景**：①必达层（4 命令）全绿，但 ②充分层（6+1 矩阵）有 1 行命中（如 06-文档 缺 README）→ 测量结论冲突
- **根因**：BR-049 三层无优先级
- **影响范围**：S3 目标值判定模糊
- **当前处理能力**：能（采纳 V3.1 S-022 = 0 红+0 命中 = 硬目标，三层 AND 关系）
- **建议修复**：BR-049 明确"三层 AND = S3 达标" + CI 中加 `s3_status = AND(三层)` 计算
- **来源标注**：[反例验证:本轮 V3.1 新增] + **V3.1:S-022**

## CE-016 [标准] WebSocket 断连风暴

- **来源标注**：[反例验证:沿用 V2.0]
