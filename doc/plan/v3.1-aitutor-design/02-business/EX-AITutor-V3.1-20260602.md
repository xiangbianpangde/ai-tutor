## 【V3.1 新增】红线检测类（EX-021）

### EX-021 红线检测失败（专项）
- **关联流程**：BP-001, BP-019, BP-021
- **异常类型**：逻辑异常 + 资源异常
- **触发条件**：4 工具链任一红 / 6+1 规范矩阵任一行有命中
- **处理策略**：
  - Ruff 错误码（F401 / T201 / BLE001）→ 删除 / 替换 logging / 具体化 except
  - Import Linter `BROKEN: <contract>` → 检查 `.importlinter` 合约定义 / `forbidden` 列表
  - Redocly 规则 ID（如 `operation-description`）→ 按规则修正
  - pre-commit 钩子失败 → 本地先 `pre-commit run --all-files` 通过再 push
  - 覆盖率 < 80% → 补正常+边界+异常 3 类用例
  - **CI 阻断**：main branch protection + required status checks 失败时 PR 不可 merge
- **恢复方式**：自动（按修复手册）/ 需人工干预（修复后重跑）
- **来源标注**：[PRD:NFR-8, F-001 验收 5.] + [调研报告:RI-004/S-020/S-021/RCFM-01~04] + [调研报告:REDOC-12/25/30/31/52/53/54]

## SA 洞察

1. **【异常分级覆盖校验】** 核心流程 12 个（BP-001/002/003/004/005/007/008/009/011/013/014/021），每个均 ≥ 4/5 类型覆盖（输入/状态/通信/资源/逻辑至少 4 类），达标。
2. **【跨流程异常】** EX-021 是 BP-001/019/021 三个流程共用的"红线未清"异常——SA 已将处理策略细化为 5 类工具的具体修复手册链接，避免下游架构师重新设计。
3. **【V3.1 增量价值】** 5 个新增红线异常（EX-021 / 029~033）= 28+5=33 个异常场景，是 V2.0 28 个的 1.18 倍，主要增量来自 BP-021 的 6+1 规范矩阵落地。
