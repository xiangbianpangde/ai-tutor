## BP-001 后端单体化启动与健康检查（F-001）【核心】

- **触发条件**：用户执行 `ai-tutor serve` 或桌面端启动器调用子进程
- **步骤序列**：
  1. 启动器 → 加载 `pyproject.toml` 依赖（uv lock 锁定）→ 产出 [DE-001 配置实体]
  2. 启动器 → 调用 FastAPI 单进程入口 `backend/main.py:app` → 产出 [DE-002 服务实例]
  3. 服务 → 校验 `data/tutor.db` 存在性 → 存在则 schema 兼容检测 → 产出 [DE-003 向后兼容报告]
  4. 服务 → 注册中间件（Session/Cache/Monitor/Pipeline/RAG） → 产出 [DE-004 中间件清单]
  5. 服务 → 启动 WebSocket 推送循环（主进程管连接） → 产出 [DE-005 WS 连接池]
  6. 服务 → 暴露 `/health` → 产出 200
- **分支条件**：
  - 旧库不兼容 → 走 `migrate_v1_to_v2()` 自动迁移 → 成功回主路径 / 失败回 EX-001
  - 端口占用 → 提示 + 自动递增重试 3 次 / 仍冲突 → EX-002
- **结束条件**：正常：`/health` 200 + WebSocket ready；异常：迁移失败 / 端口冲突
- **关联数据**：DE-001, DE-002, DE-003, DE-004, DE-005
- **关联异常**：EX-001, EX-002, EX-003, EX-004
- **来源标注**：[PRD:F-001] + [调研报告:RI-001/S-001]

## BP-003 教学策略：费曼学习法（F-003.1）【核心】

- **触发条件**：用户完成一节学习（点击"下一节"或系统判定完成）
- **步骤序列**：
  1. 学习引擎 → 从 L5 知识图谱取本节核心概念 → 产出 [DE-011 概念集]
  2. 引擎 → 状态机（FSM-State=POST_LEARN）→ 调用费曼 Prompt 模板 → 产出 [DE-012 复述题]
  3. UI → 弹窗显示复述题 + 录音/文本框 → 产出 [DE-013 用户复述]
  4. 引擎 → LLM 评分 + 追问薄弱点 → 产出 [DE-014 评分报告]
  5. 引擎 → 更新 L5 tracer 实体记忆 → 写入 audit log（trace_id 必带）
- **分支条件**：
  - 评分 < 60 → 触发追问循环 ≤ 2 次 / 仍低 → 标记本节"未掌握" + 调度 FSRS 重学
  - LLM 评分不可用 → 走 10% LLM 兜底分支，带 trace_id
- **结束条件**：正常：评分 ≥ 60 且写入 L5；异常：LLM 调用失败走兜底
- **关联数据**：DE-011, DE-012, DE-013, DE-014, DE-026 (FSRS)
- **关联异常**：EX-008, EX-009, EX-010
- **来源标注**：[PRD:F-003.1] + [调研报告:RI-002, S-019]

## BP-007 教学策略：抗幻觉多路径防御（F-003.5）【核心】

- **触发条件**：RAG 生成回答完成（BP-018 步骤 5）
- **步骤序列**：
  1. 抗幻觉引擎 → 抽取回答 N 个声明 → 产出 [DE-019 声明集]
  2. 第一层 NLI 过滤（DeBERTa-v3-large-mnli）→ 蕴含/矛盾二分定界 → 处理 ~40% 流量
  3. 第二层 SLM 法官（Galileo Luna-2 / ModernBERT 微调）→ 0.5~0.8 置信区间 → 处理 ~55% 流量
  4. 第三层 LLM 法官（Claude Haiku 4.5 / GPT-4o-mini，≥2 独立评分）→ 高歧义 ~5% 流量
  5. 多路径 → 加权裁决 → 产出 [DE-020 幻觉评分]
  6. 评分 < 阈值（如 0.7）→ 触发重检索循环（≤ 2~3 次 + 提前退出）
  7. 最终回答必带 source 引用 + NLI/LLM 法官评分记录（trace_id 必带）
- **分支条件**：
  - NLI 模型不可用 → 跳过第一层直接走 SLM
  - LLM 法官全部失败 → 走兜底分支，标记"无法验证" + 不阻塞回答
- **结束条件**：每条声明有评分 + source 引用
- **关联数据**：DE-019, DE-020, DE-024 (sources)
- **关联异常**：EX-015, EX-016, EX-017
- **来源标注**：[PRD:F-003.5] + [调研报告:RI-009, S-012 + V2.0 §2.2 HaluGate 级联, R-03, R-16]

## BP-008 教学策略：90% 状态机 + 10% LLM 兜底（F-003.6）【核心】

- **触发条件**：所有教学相关流程入口（BP-003~BP-007）
- **步骤序列**：
  1. 引擎 → 状态机匹配当前节点（FSM）→ 命中预定义规则 → 直接执行
  2. 状态机未匹配（异常/未定义状态）→ 触发 10% LLM 兜底
  3. 兜底调用 → 必带 trace_id + 输入上下文 → LLM 决策
  4. 兜底 → 必写审计日志：trace_id / 输入 / 输出 / 评分（自动 + 人工抽样）
  5. 兜底结果 → 反哺状态机（高频兜底路径 → 沉淀为新规则）
- **分支条件**：连续 3 次同状态触发兜底 → 升级为状态机规则候选（写 `state_machine_proposals` 表）
- **结束条件**：状态转移完成 / 兜底结果落库
- **关联数据**：DE-021 (state_machine), DE-022 (audit_log)
- **关联异常**：EX-018, EX-019

## BP-009 数据管线：采集→清洗→入库→治理（F-004）【核心】

- **触发条件**：用户喂入资料（CLI `ai-tutor ingest <path>` 或 UI 拖拽）

  - MinHash 假阳性高 → 调高阈值到 0.90 + 走人工抽样
  - 本地资料模式开启（BP-016）→ 跳过在线采集
- **结束条件**：文档入库 + chunks 完成

## BP-013 Agentic RAG：复杂度路由 + 重检索（F-008）【核心】

- **触发条件**：用户提问（BP-018 步骤 1）
- **步骤序列**：
  1. 路由判定器 → 计算 query 复杂度：
     - 实体数 ≥ 3 OR 跨段关键词（compare/unlike/类似于）OR query length ≥ 30 token → 代理 RAG
     - 其余 → 标准 RAG
  2. 标准 RAG（80%）：embedding 检索 → top-K → 送 LLM
  3. 代理 RAG（20%）：规划 → 多步检索 → 综合 → LLM
  4. 评估器 → 计算召回率预估 + 关键词命中率
  5. 覆盖度 < 用户设定阈值（默认 70%）→ 触发重检索循环
  6. 重检索循环 ≤ 3 轮，超出 → 报错给用户（EX-031）
  7. 产出最终上下文 → 送 LLM 生成
- **分支条件**：
  - 路由判定器置信度低 → 走更复杂的代理 RAG（安全侧）
  - 重检索 3 轮后仍不足 → 返回"已尽力检索"提示
- **结束条件**：覆盖度 ≥ 70% 或重检索轮次耗尽
- **关联数据**：DE-031 (rag_context), DE-032 (rag_eval)
- **关联异常**：EX-031, EX-032
- **来源标注**：[PRD:F-008] + [调研报告:RI-002/RI-009, S-003] + [RI-NEW-4 移交分流阈值 A/B]

## BP-014 检索/精排/缓存/监控主链路（F-009）【核心】

- **触发条件**：用户发起查询
- **步骤序列**：
  1. 预处理 → 标准化 query（去停用词、归一化）
  2. 缓存查询 → 语义阈值 0.85~0.95 命中 → 命中直接返回（latency < 100ms）
  3. 未命中 → 检索（走 BP-013 路由）
  4. 精排 → cross-encoder rerank top-K
  5. LLM 生成 → 调用 provider（OpenAI/Anthropic/Ollama 抽象层）

  7. 监控埋点 → structlog 记录 query/ts/cache_hit/llm_tokens/quality_score/trace_id/span_id
  8. 缓存写回（异步）
- **分支条件**：
  - 缓存写回失败 → 不阻塞，EX-033
  - LLM 调用超时 → 重试 1 次后降级到更小模型
- **结束条件**：回答返回 + 监控埋点完成
- **关联数据**：DE-007, DE-008, DE-009, DE-024
- **关联异常**：EX-033, EX-034

## BP-015 会话与长期记忆管理（F-010）【核心】

- **触发条件**：用户开启新会话 / 切换会话 / 跨会话实体查询
- **步骤序列**：
  1. Session 管理器 → list 已有会话 → 产出 [DE-033 会话列表]
  2. 用户选择 → 加载短期记忆（ConversationSummaryBufferMemory）→ 产出 [DE-034 短期记忆]
  3. 加载长期记忆（LangGraph Store + JSON 持久化）→ 产出 [DE-035 长期记忆]
  4. 加载跨会话实体（SQLite entities + sqlite-vec 向量）→ 产出 [DE-036 实体记忆]
  5. 每 20 轮触发摘要生成 → 更新短期记忆（控制 token 增长 < 30%）
  6. 切换会话 → 写回当前会话状态 → 切目标会话
  7. 导出/导入 → JSON 序列化
