## 后端与中间件（BR-001 ~ BR-010）

### BR-001 服务端禁 MCP 协议引用
- **规则描述**：`backend/` 不得 `import mcp.server`；客户端 SDK 允许
- **适用范围**：F-001
- **优先级**：高
- **冲突处理**：与"通过 MCP 暴露"互斥 → NB-1
- **来源标注**：[PRD:F-001] + [调研报告:S-001]

### BR-002 单进程承载所有引擎
- **规则描述**：4 个原 MCP server 引擎合并到 FastAPI 单进程
- **适用范围**：F-001
- **优先级**：高
- **来源标注**：[PRD:F-001]

### BR-003 中间件 5 类强制装配
- **规则描述**：Session/Cache/Monitor/Pipeline/RAG 必须全部注册
- **适用范围**：F-002
- **优先级**：高
- **来源标注**：[PRD:F-002]

### BR-004 监控必带 trace_id
- **规则描述**：所有埋点必须含 trace_id (32hex) + span_id (16hex)
- **适用范围**：F-002, F-009
- **优先级**：高
- **来源标注**：[PRD:NFR-5] + [调研报告:S-016]

### BR-005 缓存语义阈值
- **规则描述**：Cache 命中语义相似度阈值 = 0.85~0.95
- **适用范围**：F-002, F-009
- **优先级**：中
- **来源标注**：[调研报告:S-013]

### BR-006 缓存双后端降级
- **规则描述**：默认 SQLite；生产模式 Redis 不可用时降级 SQLite + WARN
- **适用范围**：F-002
- **来源标注**：[调研报告:S-013] + [PRD:F-002]

### BR-007 WebSocket 推送延迟
- **规则描述**：状态推送端到端延迟 ≤ 1s
- **适用范围**：F-005, F-013
- **来源标注**：[PRD:F-005, F-013] + [调研报告:S-010]

### BR-008 单会话 token 增长阈值
- **规则描述**：50 轮对话 token 增长 < 30%
- **适用范围**：F-010
- **优先级**：高
- **来源标注**：[调研报告:RI-008, S-011]

### BR-009 90% 状态机 + 10% LLM 兜底
- **规则描述**：90% 转移走状态机；10% 模糊场景走 LLM 兜底（带 trace_id + 审计）
- **适用范围**：F-003.6
- **优先级**：高
- **来源标注**：[PRD:F-003.6] + [调研报告:S-019, DSM-02/06/39]

### BR-010 兜底必带审计
- **规则描述**：LLM 兜底调用必带 trace_id + 输入/输出/评分写入 audit_log
- **适用范围**：F-003.6, F-008
- **来源标注**：[调研报告:OC-10/S-019]

## SA 洞察

1. **【规则优先级分布】** 50 条规则中"高"优先级 24 条（48%），主要分布在：监控审计 / MCP 禁用 / 100% 带源 / 红线 0 红 / 状态机兜底 / 抗幻觉 / 鉴权。
2. **【V3.1 增量价值】** 5 条红线规则（BR-046~050）= 45+5=50 条，是 V2.0 45 条的 1.11 倍；增量集中于"机器可量化"——把 6+1 规范从"约定"提升为"可 CI 阻断的硬规则"。
3. **【规则冲突检测】** BR-046（红线 0 红）与 BR-045（覆盖率 ≥ 80%）可能冲突——补测试用例会增大 backend 体积，触发 EX-023（打包体积超目标）。仲裁逻辑：覆盖率硬约束（CI 阻断），体积软约束（warn only）。
