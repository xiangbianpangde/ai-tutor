# 技术债务清单 — AITutor V3.1

> 6 项技术债务（17 模块 × [0.2, 0.5] = [3, 8]，6 在范围内 = 100%）

## TD-AR-001 ChromaDB 嵌入式 V4.0 风险

- **债务描述**：ChromaDB 嵌入式可承载 V3.1 单用户量级，V4.0 多用户后单实例难支撑
- **影响模块**：M-008 RAG 引擎、M-014 数据入库
- **风险等级**：轻度
- **产生原因**：V3.1 单用户定位与 ChromaDB 嵌入式特性匹配
- **偿还计划**：V4.0 阶段评估迁移 Qdrant 集群方案（[TD:ER-V4.0]）
- **接受理由**：V3.1 单用户量级下 ChromaDB 足够；过早优化违反 YAGNI
- **来源标注**：[调研报告:RI-008] + [AR推断:依据=BR-005 单用户量级]

## TD-AR-002 pdf2zh AGPL 协议商用待法务评审

- **债务描述**：pdf2zh 1.9.6 采用 AGPL 协议，商用前需法务评审
- **影响模块**：M-014 数据管线
- **风险等级**：中度
- **产生原因**：pdf2zh 是 PDF 双栏翻译的事实标准，AGPL 是其许可证
- **偿还计划**：V3.1 商用前完成法务评审（[调研报告:R-11] 移交）
- **接受理由**：V3.1 暂不商用，可接受；商用前必须解决
- **来源标注**：[调研报告:R-11] + [AR推断:依据=pdf2zh 1.9.6 协议]

## TD-AR-003 Nuitka 打包体积待实测

- **债务描述**：Nuitka onedir + UPX 实际打包体积（chromadb / sentence-transformers 依赖）需 build 实测
- **影响模块**：M-015 打包调度
- **风险等级**：中度
- **产生原因**：理论压缩比 30~50%，但 chromadb 内嵌数据文件可能膨胀
- **偿还计划**：V3.1 release 前完成 3 平台 build 实测（[调研报告:RI-NEW-3] 移交）
- **接受理由**：Nuitka onedir 是事实标准方案，build 实测是必经路径
- **来源标注**：[调研报告:RI-NEW-3] + [TD:SR-003] + [TD:ADR-009]

## TD-AR-004 Ruff 0.x → 1.0 升级窗口

- **债务描述**：Ruff 1.0 前可能有破坏性 API 变更（[调研报告:REDOC-09]）
- **影响模块**：M-016 红线编排、全部模块
- **风险等级**：轻度（已被 DE-048 锁版本缓解）
- **产生原因**：Ruff 快速迭代期
- **偿还计划**：V3.2 走 TDD 渐进式升级（先 5% 规则启用 → 全量）
- **接受理由**：DE-048 锁版本 + CI 阻断已完全缓解；升级路径明确
- **来源标注**：[调研报告:RI-004/REDOC-09] + [TD:ADR-010]

## TD-AR-005 M-008 / M-016 内聚度待 V3.2 拆分

- **债务描述**：M-008 内聚度 3/6（最低）/ M-016 内聚度 4/6，TD 已记录 V3.2 拆分
- **影响模块**：M-008、M-016
- **风险等级**：轻度（TD 已认可接受上沿）
- **产生原因**：BR-002 单进程 + BR-046~050 横切治理强制需求
- **偿还计划**：V3.2 触发条件 100 用户时拆分（[TD:ER-V3.2]）
- **接受理由**：TD 已冻结 D7=81%，接受当前 17 模块上沿；当前通过子能力命名空间隔离副作用
- **来源标注**：[TD:SR-001/002] + [TD:ER-V3.2]

## TD-AR-006 M-013 长期记忆 LRU 淘汰策略

- **债务描述**：长期记忆 LRU 淘汰最旧 10% 可能误删重要事实
- **影响模块**：M-013 会话编排
- **风险等级**：轻度
- **产生原因**：V3.1 暂未实现重要性评分
- **偿还计划**：V4.5 引入"重要性 × 时间衰减"评分（[TD:ER-V4.5] + [TD:CR-001]）
- **接受理由**：单用户场景下 LRU 误删风险可控；V4.5 有明确升级路径
- **来源标注**：[TD:ADR-012] + [TD:SR-007]
