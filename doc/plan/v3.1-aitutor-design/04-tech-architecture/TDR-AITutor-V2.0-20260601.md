## TDR-001 Python 3.11 + FastAPI 0.115 核心语言框架选择

- **决策状态**：已接受
- **决策内容**：选择 Python 3.11.x + FastAPI 0.115.x 作为核心语言与 Web 框架
- **决策理由**：
  1. 调研报告 10 大技术决策矩阵 100% 对齐 Python 生态（py-fsrs/HaluGate/Hindsight）
  2. 与 TD 5 类中间件强制装配（[SA:BR-003]）天然契合
  3. 团队已掌握，学习成本为 0
- **拒绝的替代方案**：
  - Node.js 22 + Express：RAG 生态不成熟，无 py-fsrs 等价物（[调研报告:§4]）
  - Go + Gin：生态更弱，库丰富度不足
- **影响范围**：M-001~M-010 全部模块 + 全部 IF
- **相关 TDR**：TDR-002/003
- **来源标注**：[调研报告:§4 关键技术决策矩阵] + [TD:SA-D]

## TDR-002 抗幻觉采用 HaluGate 三级级联架构

- **决策状态**：已接受
- **决策内容**：NLI（~40%）→ SLM（~55%）→ LLM 法官（~5% ≥2 独立打分）三级级联
- **决策理由**：
  1. [调研报告:NLI-05] DeBERTa-v3-large-mnli 在 HaluEval 上保形 FPR = 100%，不能作单点
  2. [调研报告:NLI-01] HaluGate 实测 400x TCO 降低（$4,200/月 → $180/月）
  3. [调研报告:NLI-12/27/29/30] 异构 LLM 法官防自恋偏差（NLI-24/26）
- **拒绝的替代方案**：
  - 单层 LLM 法官：成本高 + 仍可能自恋偏差
  - 嵌入相似度：FPR 88-100%（[调研报告:NLI-05/48]）
- **影响范围**：M-003 + DE-019/DE-020 + 性能 NFR
- **相关 TDR**：TDR-009
- **来源标注**：[调研报告:NLI-01/05/13] + [SA:BP-007] + [ADR-003]

## TDR-003 缓存后端采用 SQLite+Redis 双后端

- **决策状态**：已接受
- **决策内容**：默认 SQLite LRU（[TS-005]），可选 Redis 7.4（[TS-007]）
- **决策理由**：
  1. [调研报告:CACHE-13/49] SQLite+LRU 二次 latency -50%（[SA:BR-031]）
  2. [调研报告:RI-010] Redis 亚毫秒 + 1200+ QPS
  3. 双后端策略降低部署门槛（[调研报告:S-013]）
- **拒绝的替代方案**：
  - 纯 Redis：增加部署依赖
  - 纯 SQLite：无法水平扩展（V-3 多用户时）
- **影响范围**：M-005 + DE-007 Cache + API-013 缓存键
- **相关 TDR**：TDR-006
- **来源标注**：[调研报告:CACHE-13/49/RI-010] + [SA:DE-007]

## TDR-007 全局循环计数器 max_total_rounds=5

- **决策状态**：已接受
- **决策内容**：M-005 引入 `max_total_rounds=5` 全局计数器
- **决策理由**：
  1. [SA:CE-010] 重检索 + 抗幻觉双重死循环识别
  2. 单层上限（≤3）不能阻止跨层联合
  3. 全局计数保证可终止
- **拒绝的替代方案**：
  - 让 BP-013 和 BP-007 各自计数：仍可能联合超限
  - 不限：死循环风险
- **影响范围**：M-005 Pipeline 编排 + M-003 抗幻觉
- **相关 TDR**：TDR-002
- **来源标注**：[SA:CE-010] + [ADR-005]
