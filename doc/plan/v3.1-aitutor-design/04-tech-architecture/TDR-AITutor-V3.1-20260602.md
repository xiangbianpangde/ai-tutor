## TDR-001 核心技术栈：Python + FastAPI + SQLite + ChromaDB

- **决策状态**：已接受
- **决策内容**：采用 Python 3.11 + FastAPI 0.115 + SQLite 3.46 + ChromaDB 0.5 单进程全栈
- **决策理由**：
  - [调研报告:RI-001] FastAPI 单进程可承载 V3.1 量级（与 M-001~M-017 5MW + 21 编排匹配）
  - [调研报告:RI-010] SQLite WAL 模式在单用户场景可支撑 100+ 并发读
  - [调研报告:RI-008] ChromaDB 嵌入式 + HNSW 满足 RAG 检索性能
  - [TD:BR-002] PRD 强制单进程
  - [TS-AITutor] 18 选型全通过 6 项合理性检查
- **拒绝的替代方案**：
  - Node.js：异步好但 AI 生态弱（MCP/ARA 来源少）
  - Go：性能好但 LLM 客户端少
  - PostgreSQL：运维重，单用户杀鸡用牛刀
- **影响范围**：M-001~M-017 全部模块、CI 流程、桌面端打包
- **相关TDR**：TDR-002、TDR-003
- **来源标注**：[调研报告:RI-001/008/010] + [TD:BR-002] + [TS-AITutor]

## TDR-002 架构模式：分层 + 插件化 + 事件总线

- **决策状态**：已接受
- **决策内容**：采用混合架构（分层为核心 + 插件化注入可替换引擎 + 事件总线解耦 WS/FSM/兜底）
- **决策理由**：
  - [TD:ADR-001] BR-002 单进程 + BR-003 5MW + WS ≤1s + 翻译/NLI 可插拔
  - 分层满足 L0~L5 清晰边界
  - 插件化使 NLI/翻译/OCR 可替换（V4.0 升级路径）
  - 事件总线解耦 WS 推送 + FSM 兜底审计
- **拒绝的替代方案**：
  - 纯微服务（违背 BR-002 / 运维成本高 / 5MW 强耦合）
  - 纯插件化（核心不稳定）
- **影响范围**：全部 17 模块、CI、桌面端
- **相关TDR**：TDR-001、TDR-005
- **来源标注**：[TD:ADR-001] + [调研报告:RI-001]

## TDR-003 单进程承载（FastAPI + asyncio）

- **决策状态**：已接受
- **决策内容**：4 个原 MCP server 引擎合并到 FastAPI 单进程
- **决策理由**：
  - [TD:BR-002] PRD 强制
  - 简化部署（一个 exe）
  - asyncio 可承载 21 编排（[调研报告:RI-001] 验证）
- **拒绝的替代方案**：
  - 多进程（端口管理复杂 / IPC 成本）
  - 多容器（违背桌面端单 exe 定位）
- **影响范围**：M-001 服务入口、全部 5MW
- **相关TDR**：TDR-001
- **来源标注**：[TD:ADR-002] + [TD:BP-001]

## TDR-004 5 类中间件强制装配

- **决策状态**：已接受
- **决策内容**：Session/Cache/Monitor/Pipeline/RAG 必须全部注册
- **决策理由**：

- **相关TDR**：TDR-001
- **来源标注**：[TD:ADR-003] + [TD:BP-002]

## TDR-005 缓存双后端（SQLite 默认 / Redis 可选）

- **决策状态**：已接受
- **决策内容**：默认 SQLite；生产模式 Redis 不可用时降级 SQLite + WARN
- **决策理由**：
  - [TD:BR-006] 本地优先 + 单用户场景
  - [调研报告:RI-010] SQLite 性能足够
  - 自动降级保证可用性
- **拒绝的替代方案**：
  - Redis 强制（增加单用户部署成本）
- **影响范围**：M-005 Cache 中间件
- **相关TDR**：TDR-006
- **来源标注**：[TD:ADR-004] + [调研报告:RI-010/CACHE-49]

## TDR-006 90% FSM + 10% LLM 兜底

- **决策状态**：已接受
- **决策内容**：90% 状态机 + 10% LLM 兜底（带 trace_id + 审计）
- **决策理由**：
  - [TD:BR-009/010] PRD 强制
  - [调研报告:RI-OC-10/DSM-02/06/39] 状态机可解释 + LLM 兜底灵活
  - audit_log 全 NOT NULL 必传
- **拒绝的替代方案**：
  - 纯 LLM（成本高 / 不可控 / 延迟大）
  - 纯 FSM（覆盖率低 / 边界 case 多）
- **影响范围**：M-009 教学编排、M-007 Pipeline、DE-023/024 audit_log
- **相关TDR**：TDR-007
- **来源标注**：[TD:ADR-005] + [调研报告:RI-OC-10]

## TDR-007 NLI 100% 带源 + 重检索 ≤3 轮

- **决策状态**：已接受
- **决策内容**：NLI 评分 < 0.7 触发重检索 ≤ 3 轮；阈值未达标注"无法确认" + 切 web 搜索
- **决策理由**：
  - [TD:BR-016] 抗幻觉 100% 带源
  - [TD:BR-017/018] 重检索上限
  - [调研报告:RI-009/HAL-16/NLI-01] 抗幻觉级联架构验证
- **拒绝的替代方案**：
  - 纯 NLI（部署成本高）
  - 纯 LLM（不可解释）
- **影响范围**：M-008 (NLI 子) / M-007 Pipeline
- **相关TDR**：TDR-005
- **来源标注**：[TD:ADR-006] + [调研报告:RI-009]

## TDR-009 打包：覆盖率硬约束 / 体积软约束

- **决策状态**：已接受
- **决策内容**：覆盖率（≥80%）CI 阻断；体积 CLI < 50MB / GUI < 200MB 改 warn only
- **决策理由**：
  - [TD:CE-011] 跨流程风险仲裁
  - 覆盖率优先（质量底线）

- **拒绝的替代方案**：
  - 双硬约束（CE-011 复现）
- **影响范围**：M-016 红线编排、M-015 打包调度
- **相关TDR**：TDR-008
- **来源标注**：[TD:ADR-009] + [TD:CE-011]
