# BDD 规格：06 — 数据管线（采集→清洗→结构化）

> 对应功能点：#6 | 设计文档：[设计文档-数据管线](../plan/design/设计文档-数据管线.md)

## 功能 1：PDF 多引擎采集

### 场景 1：MinerU 处理中文学术 PDF
- 前置条件：MinerU 已安装
- 操作步骤：
  1. 导入中文教材 PDF（含公式/表格）
- 预期结果：输出 Markdown 文件，公式转为 `$$...$$`，表格转为 Markdown table

### 场景 2：PyMuPDF fallback
- 前置条件：MinerU 未安装或失败
- 操作步骤：
  1. 导入简单文本 PDF
- 预期结果：自动降级到 PyMuPDF 提取纯文本，输出 Markdown 文件

### 场景 3：pdf2zh fallback
- 前置条件：导入外文 PDF，用户勾选"翻译为中文"
- 操作步骤：
  1. 导入英文教材 PDF + translate=true
- 预期结果：pdf2zh 翻译并输出中文 Markdown

---

## 功能 2：文本清洗

### 场景 1：去除页眉页脚
- 前置条件：PDF 转出的 MD 含重复页眉（如每页"第一章 极限"）
- 操作步骤：
  1. 管线自动清洗
- 预期结果：页眉页脚被移除，仅保留正文

### 场景 2：修复 OCR 断行
- 前置条件：PDF 转出的 MD 有长短行混合（每 10 字就换行）
- 操作步骤：
  1. 管线自动清洗
- 预期结果：短行合并为完整段落（中文 < 20 字的行合并到上一行）

### 场景 3：去重
- 前置条件：教材不同章节有重复的摘要段落
- 操作步骤：
  1. 管线自动清洗
- 预期结果：相邻高度相似的段落合并为一条

---

## 功能 3：结构化

### 场景 1：章节检测
- 前置条件：清洗后的文本含"第一章 xxx" / "1.1 xxx" 标题
- 操作步骤：
  1. 管线自动结构化
- 预期结果：输出标准 `#` `##` `###` Markdown 层级标题

### 场景 2：公式保护
- 前置条件：文本含 `$$ \lim_{x \to 0} f(x) $$` 和行内 `$E=mc^2$`
- 操作步骤：
  1. 管线自动结构化
- 预期结果：公式块不被清洗/断行破坏，原样保留

---

## 功能 4：多源采集

### 场景 1：本地文件拖拽
- 前置条件：用户拖拽 3 个文件（.pdf + .md + .txt）到知识库页面
- 操作步骤：
  1. 拖拽到上传区
- 预期结果：3 个文件依次采集→清洗→结构化，合并为一个 corpus

### 场景 2：URL 网页采集
- 前置条件：输入技术博客 URL
- 操作步骤：
  1. 在知识库页面粘贴 URL → 点击"导入"
- 预期结果：httpx 抓取 → readability 提取正文 → 清洗 → 追加到 corpus

### 场景 3：异常场景 — 不支持的文件格式
- 前置条件：用户拖拽 .docx 文件
- 操作步骤：
  1. 拖拽到上传区
- 预期结果：提示"暂不支持 .docx 格式，请先转为 PDF 或 Markdown"
