# BDD 规格：03 — 中间件层（Session/File/Cache/Monitor）

> 对应功能点：#3 | 设计文档：[设计文档-中间件层](../plan/design/设计文档-中间件层.md)

## 功能 1：SessionManager — 多会话并行

### 场景 1：列出用户所有会话
- 前置条件：用户有 3 个会话（2 active, 1 completed）
- 操作步骤：
  1. `GET /api/tutoring/sessions?user_id=yhn`
- 预期结果：返回 3 条记录，每条含 subject_id / summary / last_active_at / token_usage

### 场景 2：会话切换
- 前置条件：用户有 session-A（高等数学）和 session-B（机器学习）
- 操作步骤：
  1. 当前正在 session-A
  2. 切换到 session-B，WebSocket 重连到新 session_id
- 预期结果：session-A 自动保存状态，session-B 恢复上次进度（含 strategy_internal）

### 场景 3：会话自动摘要
- 前置条件：session 已结束（status=completed）
- 操作步骤：
  1. 会话关闭触发自动摘要生成
- 预期结果：`session_summaries` 表新增一条记录，summary 包含"学过 X 概念 / 薄弱 Y / 下一步 Z"

### 场景 4：Token 计数
- 前置条件：会话中有 5 次 LLM 调用
- 操作步骤：
  1. 查 session 的 token 使用
- 预期结果：返回 input_tokens / output_tokens / total_tokens，数值 > 0

### 场景 5：异常场景 — 过期会话清理
- 前置条件：有 2 个会话 8 天未活跃
- 操作步骤：
  1. 系统自动清理（或手动触发 cleanup）
- 预期结果：过期会话标记为 expired，前端列表不再显示

## 功能 2：FileManager — 统一文件管理

### 场景 1：按用户/科目组织文件
- 前置条件：用户 yhn 导入"高等数学"
- 操作步骤：
  1. 采集 PDF → `data/yhn/gaoshu/corpora/gaoshu_xiace.md`
  2. 构建 KG → `data/yhn/gaoshu/knowledge_graphs/v1/`
- 预期结果：文件路径人类可读，无 UUID 目录名

### 场景 2：导出文件
- 前置条件：已生成复习计划
- 操作步骤：
  1. 导出复习计划 → `data/yhn/gaoshu/exports/review_plan_2026-05-29.md`
- 预期结果：文件写入正确路径

## 功能 3：CacheLayer — LLM 调用缓存

### 场景 1：缓存命中
- 前置条件：已请求过"解释导数定义"（LLM 返回 500 token）
- 操作步骤：
  1. 再次请求相同的"解释导数定义"（相同 provider + model + messages + temp）
- 预期结果：直接返回缓存结果，不调 LLM API，token 消耗为 0

### 场景 2：缓存过期
- 前置条件：概念定义缓存 TTL=24h，已过期
- 操作步骤：
  1. 请求过期缓存对应的查询
- 预期结果：重新调 LLM API，更新缓存

### 场景 3：缓存统计
- 前置条件：10 次请求，7 次命中
- 操作步骤：
  1. 查缓存统计
- 预期结果：hit_rate=70%，saved_tokens > 0

## 功能 4：MonitorMiddleware — 质量追踪

### 场景 1：记录检索质量
- 前置条件：执行一次 RAG 检索
- 操作步骤：
  1. 检索"ACP 大模型应用"
  2. 评估 relevance_score
- 预期结果：`monitor_records` 表新增一条 type=retrieval 记录，含 query / result_count / relevance_score

### 场景 2：生成质量周报
- 前置条件：7 天内有 50 次检索 + 100 次回答
- 操作步骤：
  1. 请求生成质量报告（period=weekly）
- 预期结果：包含 avg_retrieval_relevance / avg_answer_quality / 质量趋势图数据
