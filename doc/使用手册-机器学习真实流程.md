# AI-Tutor 使用手册 —— 以「机器学习基础」真实学习流程为例

> 本手册的每一步都来自 2026-08-29 的真实运行记录：MiniMax-M3 真实判分、
> BKT 掌握度真实爬升（0.394 → 0.9998）、事件流与仪表盘为实际截图状态。
> 运行记录存于本机 `/tmp/demo-session-log.json` 与后端数据库。

## 1. 启动

需要两个进程（仓库根目录）：

```bash
# 1) 后端（FastAPI，127.0.0.1:18501）
.venv/bin/python -m backend.main

# 2) 前端（Vite dev server，localhost:5199；打包后用 Electron 外壳）
cd frontend/renderer && npx vite --port 5199
```

浏览器打开 `http://localhost:5199/`。左侧导航：仪表盘 / 学习中心 / 知识
图谱 / 复习 / 设置；底部绿点表示 WebSocket 实时通道已连。

## 2. 配置 LLM（MiniMax）

进入「设置」页：

1. **Provider** 选 `DeepSeek` / `OpenAI` / `Ollama（本地）` / `自定义`——
   四者只是预设不同，**Base URL 与 Model 全部可手改**。MiniMax 选
   `自定义` 或 `DeepSeek` 均可（MiniMax 端点 OpenAI 兼容）。
2. 填入：
   - **Base URL**：`https://api.minimaxi.com/v1`（国内站；海外站为
     `https://api.minimax.io/v1`）
   - **API Key**：你的 MiniMax key（`sk-…`）
   - **Model**：`MiniMax-M3`
3. 先点 **「测试连接」**——后端用该配置发一条 1-token 探测，显示
   `连通（MiniMax-M3，xxxx ms）`；失败会给出具体原因。
4. 点 **「保存并应用」**——配置**热替换**到教学管线，无需重启后端。
   下方「当前生效」会实时回显（key 打码为 `sk-***尾4位`）。

安全语义：

- API key 只存两处：本机浏览器 localStorage（回显用）+ 后端**进程内存**
  （调用用）。不落盘、不入日志、不出现在任何接口响应里。
- 后端重启后运行时配置失效（回到环境变量选择链）；在设置页重新
  「保存并应用」即可恢复。
- 首次使用向导（第 1 步配置 LLM）与设置页同构，完成时会自动应用。

> ⚠️ key 在聊天中明文出现过的，按泄露候选处理，建议尽快在 MiniMax
> 控制台轮换。

## 3. 导入资料建科目

进入「学习中心」→「导入资料新建科目」→ 粘贴带 `#` / `##` 标题的
Markdown → 确认。

后台流水线：写入语料 → 按 `##` 标题切分概念（纯规则，免 LLM，秒级）
→ 建知识图谱 → 创建科目。完成后「我的科目」出现科目卡（如
`机器学习基础 · 6 概念`），点击选中 →「开始学习」。

> 已知限制：**同一资料名重复导入会复用同名科目行**（slug 全局唯一），
> 图谱会重建，但科目属主仍是首次导入的用户。换用户学习同一资料名时，
> 建议换一个资料名，或由管理员修正属主。

## 4. 真实学习循环

点「开始学习」后进入会话，教学引擎按知识图谱拓扑序驱动：

```text
讲解(explain) → 示例(show_example) → CHECK 开放题(ask_question)
      ↑                                        │
      └──── 掌握度达标后进入下一概念 ←── LLM 判分 ──┘
```

- **CHECK 题是开放问答**（如"用你自己的话说说机器学习基础是什么？"），
  用自己的话作答，**MiniMax-M3 实时判分**（实测 2-5 秒/次）。
- 判分返回：
  - `correctness`：correct / partial / incorrect（诚实分级，不放水）
  - `feedback`：中文针对性点评（指出缺哪块拼图）
  - `error_analysis`：错误类型与根概念定位
  - `mastery_update`：BKT 掌握度更新（本次实测 0.394 → 0.858 → 0.982
    → 0.9998，partial 只涨到 0.154——判分严格时推进明显变慢，符合
    学习科学设计）
- 全部 6 个概念达标后会话完成；中途可随时离开，会话状态保留。

真实运行节选（第一次作答过于笼统）：

```json
{"correctness": "partial",
 "feedback": "你关于机器学习基础的思考有对的地方。概念整体框架掌握得不错，
              建议补一块拼图：想想模型训练时如何一步步减小误差（梯度下降），
              以及怎样判断模型在新数据上是否真的靠谱（模型评估与过拟合）。",
 "mastery_update": {"new_mastery": 0.154}}
```

补全回答后再答即 `correct`，掌握度跳升到 0.645——这就是"真实学习"的
反馈闭环。

## 5. 仪表盘与事件流

- **我的科目会话**：进行中会话数（点开可看会话 ID）
- **实时事件流**：每条判分产生 `teaching.responded` 事件（含判定结果）
- **最近学习**：最近会话与状态
- 子系统五胶囊（db/cache/sessions/tasks/events）全绿 = 后端健康

## 6. 常见问题对照（全部来自本次真实踩坑）

| 现象 | 原因 | 处理 |
|---|---|---|
| 判分报 `LLM_REQUEST_FAILED: HTTP Error 401` | 环境变量里残留**旧/失效 key**（如 `.zshrc` 里的 `MINIMAX_API_KEY`），且设置页配置未应用 | 设置页重新「保存并应用」（运行时配置优先于 env）；或清除环境里的旧 key |
| `LLM_CONFIG_INVALID: base_url 必须…` | Base URL 不是 http/https 绝对地址 | 检查拼写；本地 Ollama 用 `http://localhost:11434/v1` |
| 测试连接超时 | 端点不可达 / 系统代理拦截 | 后端直连（代码已绕系统代理）；检查代理软件对该域名的分流规则 |
| 学习中心"还没有科目" | 科目属主与当前用户 ID 不一致（同 slug 二次导入的已知边界） | 核对「高级选项」里的用户 ID；或换资料名重新导入 |
| 后端重启后 LLM 失效 | 运行时配置存于进程内存 | 设置页重新「保存并应用」（10 秒） |
| 事件流时间显示异常 | 事件时间戳单位换算 bug（已记录待修） | 不影响判分与学习 |

## 7. 架构一句话

前端（React/Vite）→ 后端 FastAPI（`/api/*`，teaching 管线驱动知识图谱
拓扑序 + BKT 掌握度 + LLM 判分）→ 可热替换的 OpenAI 兼容 LLM 端点。
判分与掌握度是真实计算；"48 小时学完一科"是产品愿景而非已验证结论。
