## 一、逐问题分析

### #1 没用好调研工具：没清洗、没整理、格式混乱

- **现象**：clean 后的语料仍是 13 份近重复网页的机械堆叠；`quality.json` 里 score=0.113、0.14 的文件照常入料（`data/corpora/.../clean/quality.json`，`issues:[]` 全空）。
- **根因**：
  1. `research_adapter.py:99` 只跑 `stages=["collect","clean"]`，research-tool 的 extract/organize 被有意跳过，注释称"概念抽取交给本项目 KG builder"——但 KG builder 是标题正则（R2），承接不了"整理"职责 → **整理环节系统性缺位**。
  2. `research_adapter.py:55-71` `_merge_markdown` 用 `f.stem`（来源文件名）当 `##` 标题，正文里的 HTML 元数据注释（`<!-- source/title/fetched -->`）原样保留。
  3. 清洗质量分数无门槛：score 0.113 的文件与 0.835 的同等入料，无任何过滤/告警。
  4. 13 个来源讲同一主题，无跨源去重与归并。
- **修复**：v1 — 合并时取 `<!-- title: ... -->` 当节标题、剥元数据注释、正文标题降级、过滤清洗后几乎无残文的来源（注：quality.json 的 score 实为"清洗保留比例"而非质量分，不可直接当过滤阈值）（FIX-B）；KG 侧噪声标题过滤+去重（FIX-A）。v2 — 数据管线引入 LLM 整理(organize)阶段（设计文档-数据管线 / v3.1 M-014）。
- **落点**：v1 代码（research_adapter + kg_enrich_adapter）+ v2 管线。

### #2 降阶法第一阶段让人读 5 万多行 md

- **现象**：`00_merged_complete.md` 实测 **75,393 行**；`acp_run_full.py:237-239` 原样复制为《ACP大模型应用_完整学习资料.md》交给用户；后来的 121 份拆分（`降阶拆分/README.md` 自述"54,778 行拆成 121 份"）是 Claude Desktop 人工干的。
- **根因**：系统里**不存在"可读学习材料"这一产物**。digest 的 notes/mindmap 从 KG 概念生成（继承 35% 噪声），唯一完整可读物 = 原始拼接语料。降阶法状态机管"问答节奏"，不管"阅读材料分片"。
- **修复**：v1 — digest 新增 `study_pack` 产物：按章节把语料拆成 15-30 分钟/份的小文件 + 索引 + 预估阅读时长（把人工拆分脚本产品化，FIX-J）。v2 — 前端阅读器按 Phase 取片。
- **落点**：v1 代码（digest_mcp）。

### #3 可视化等于放屁

- **修复**：v1 — 先修数据（FIX-A/B 后 KG 干净，可视化才有意义）。v2 — #5 可视化功能点（React + 真图表：KG 力导图、遗忘曲线、掌握度热力图），按设计文档-前端桌面应用执行，**验收红线：每张图必须回答一个学习者问题**（"我哪里弱""今天该复习什么"），否则不算完成。

### #4 MCP 调用存在巨大问题，直接放弃使用 MCP

- **现象**：用户弃用 MCP；项目自己的 demo 脚本全部绕开 MCP——`acp_run_full.py:43` `fn = lambda x: getattr(x, "fn", x)` 直接拆 FastMCP 包装调底层函数。

### #9 检索覆盖不足（考试要 50%，搜到 45%，得 35%）

### #11 缺缓存 / 监控

- **现象**：同样的问题每次都重新算；检索与回答质量无记录。

- **落点**：v2。

### #16 阶段 1.0→2.0 没有过渡，强度过大

- **现象**：实测 15 步：1 步问答后**连续 14 步 give_exercise**，无任何讲解穿插。
- **根因**（两个，第一个是硬 bug）：
  1. **PRACTICE 死循环**：`engine.respond()` 固定发 `answered` 事件（engine.py:517），而 reduction 的 PRACTICE 态只认 `practice_done`（reduction.py:138）；FastMCP/脚本对练习作答必走 respond → 事件被宽容语义吞掉 → 状态永远停在 PRACTICE → 永远出题。
  2. 策略形态本身陡峭：jiangjie GOAL 一句话讲解后连续 5 原子问 + 7 误解问 + 4 重构问 + 1 验证题 = 17 连问零讲解（jiangjie.py:61-63 默认值）；reduction 也是 INTRO/EXPLAIN 两步后全是问。"读 5 万行（阶段1）→ 无限刷题（阶段2）"之间没有任何渐进。
- **修复**：v1 — PRACTICE 接受 answered 事件并按 correctness 推进（FIX-E）；降阶法 REDUCE 每 2 个原子问之间插一步小结讲解（节奏缓冲）暂缓，先修死循环。v2 — M-012 阶段校准（难度斜坡）。
- **落点**：v1 代码（死循环必修）+ v2 斜坡。

### #18 长期使用出现强幻觉

- **现象**：长会话后 AI 输出越来越飘。
- **根因**：
  1. **判分器不看题**（最大教学幻觉源）：`LLMScorer.score(concept, answer)` 没有 question 参数（llm_scorer.py:133），prompt 只比对"概念定义 vs 答案"（:39-61）→ 答非所问只要沾概念边就 correct（实测：判断题给套话答案 → correct +0.298）。判出来的"掌握度"是幻觉，后续教学决策全部建立在幻觉上。
  2. 教学内容生成不接语料（content_generator 只看 concept 字段，无 RAG 接地）→ LLM 自由发挥。
  3. Claude Desktop 长对话上下文膨胀（架构层，v1 无解）。
- **修复**：v1 — 判分器加题目感知 + "答非所问降级"规则（FIX-D）。v2 — RAG 接地 + HaluGate（M-008/M-016）+ 会话总结控上下文（M-004）。
- **落点**：v1 判分 + v2 接地。

### #22 每个 markdown 标题当一个 concept（新增）

- **现象**：356 概念中 126 个噪声（35%）；「`============`」「`01-edu.aliyun.com-087e03`」、Python 注释整句都成了概念，且第一个被教的概念就是文档标题。
- **根因**：
  1. `kg_enrich_adapter.py:37-42` `_iter_headings` 逐行正则 `^#{1,6}\s`，**不跳过 ``` 围栏代码块** → 代码里的 Python 注释 `# ====`、`# 指令：` 全部成为概念；
  2. `research_adapter.py:68` 文件名当标题 → 文件名成概念；
  3. 无噪声标题过滤（分隔线/URL/整句/超长）、无同名去重（13 个近重复来源 → 大量重复概念）；
  4. concept/full 深度只是对"标题概念"做 LLM 富化（kg_builder.py:118 `_build_toc` 是一切的起点），**从不重新识别什么才是概念**。
- **修复**：v1 — FIX-A：围栏跳过 + 噪声标题过滤 + 标准化去重；FIX-B：合并层标题治理。v2 — M-014 用 LLM 从内容抽概念（标题只作 anchor 不作概念全集）。
- **落点**：v1 代码（本轮核心修复）+ v2 内容级抽取。

## 三、对 v2/v3.1 计划的回灌结论

1. **优先级修正**：v2 开发顺序中，**#6 数据管线（整理环节）应与 #1/#2 骨架同波**——本次取证表明数据质量是一切下游（教学/可视化/复习）的瓶颈，比前端更紧迫。
2. **验收红线补充**（写入对应 BDD spec）：
   - 数据管线：KG 概念噪声率 < 5%（以本次 126/356=35% 为基线）；语料必须有"整理"产物而非拼接。
   - 教学引擎：任意状态收到 respond 必须可推进或显式报错（禁宽容吞事件）；判分 prompt 必含题目原文。
   - 可视化：每张图回答一个学习者问题，DB 表格 dump 不算可视化。
3. **MCP 弃用决策确认**：v1 的 32 个 MCP tool 不再维护新功能，仅作 v2 engines/ 的迁移源。
