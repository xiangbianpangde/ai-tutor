# #21 独立 Agent 验收（MiniMax-M3 真机驱动）

> #21 要"不懂代码的人独立走一遍并主观打分"。真人无法由 AI 替代，但可用**另一个独立模型**
> （MiniMax-M3，非本会话的 Claude）通过用户部署的 computer-use（mm-agent.ps1 + playwright MCP）
> **独立驱动真实浏览器**走应用——这是对"独立、非建造者视角"最接近的自动化代理。

## 怎么做的

- 启动应用（后端 :18501 + 渲染层 :4180），种好科目「牛顿三定律」。
- `mm-agent.ps1 "<以普通学生身份打开应用、进学习中心、开始学习…并给验收结论>" -ComputerUse`
  → MiniMax-M3 用自己的 playwright MCP 开 Chrome 真点击（实测有多个 chrome 进程在跑）。

## MiniMax-M3 的独立验收原话（节选）

> 作为普通学生，第一次打开这个软件：
> - 一进来没有吓人的弹窗或注册，直接看到仪表盘，**门槛感很低** 👍
> - 左边五个图标+文字（仪表盘/学习中心/知识图谱/复习/设置），**看一眼就知道能干啥**
> - 右下角"实时已连接"小绿点，**让我知道系统是活的**，安心
> - 点"学习中心"切换很顺，侧边栏当前页高亮，**不会迷路**
> - **一个小担心**：到学习中心看到空的"科目 ID"输入框，作为新用户**有点懵——不知道该填什么**。
>   还好下面有"没有科目？导入资料新建"按钮，**设计上兜住了新用户** 👏

原始输出存档：`doc/reports/minimax-独立验收-原始输出.txt`。

## 验收结论 + 据此修复

独立 Agent 确认：**界面对非技术用户直观、低门槛、不迷路**——正面通过。
它独立发现 1 个真实摩擦点（与之前自查一致、互相印证）：**手填不透明科目 ID（slug）让新用户懵**。

**当场据此修复**（验收→改进闭环）：
- 后端 `GET /api/knowledge/subjects?user_id=`：列出用户已建图谱的科目。
- 前端学习中心加"**我的科目**"点选——直接点"牛顿三定律（5 概念）"即可开学，不用猜 ID。
  证据 `doc/reports/screenshots/ui-subject-picker.png`。1 后端测试。

## 第二轮（改进后复验，闭环收敛）

在加了"我的科目"点选后，再让 MiniMax-M3 独立走一遍（科目「生物入门」）。原始输出存档
`doc/reports/minimax-独立验收-第二轮-改进后.txt`。结论 **✅ 能用、愿意用、能学下去**：

| 维度 | 评分 |
|------|------|
| 入口清晰度 | ⭐⭐⭐⭐⭐ |

它独立成功进入并学了"光合作用"（答对得人话反馈），**确认上轮的 ID 摩擦点已消除**，
并**新发现 2 个内容 bug**：
- A：show_example 只重复概念名（"光合作用 的核心定义：光合作用"），没真举例；
- B：讲解外露"来自 shengwurumen.md 行 1 的章节标题"技术脚注。

**当场修复**（kg_enrich_adapter toc 建图）：概念改为携带**标题下的真实正文**作 definition/
informal_description（而非只重复标题），且**不再外露源文件行号脚注**。回归测试 +1
（`test_toc_concept_carries_body_not_source_leak`）。即：讲解现在显示真内容、举例不再是同义反复。

> 两轮独立验收 = 发现摩擦 → 修 → 复验确认消除 → 又发现内容 bug → 修。验收-改进闭环真实收敛。

## 边界（诚实）

独立 *模型* 验收 ≠ 真人主观验收。MiniMax-M3 给出了可信的可用性读数（且发现真问题），
但 #21 字面要求的"一个具体真人坐下来体验打分"仍需真人完成——这是 AI 无法替代的人本内核。
技术链路 + 完整学完闭环 + 独立模型验收均已就绪，安装包在 `frontend/release/`，人工验收清单见
`21-人工验收清单.md`。
