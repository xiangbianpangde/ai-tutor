## A. F-001 后端单体化 相关

### [S-001] 验收标准 #3 调整
- **指向条目**：PRD §3.1 F-001 验收标准 ③
- **问题描述**：`grep -r "mcp" backend/ = 0` 过于严格，会导致演进受限（如未来需要从客户端 SDK 引用 MCP 类型）
- **建议改动**：将验收改为 `grep -r "from mcp.server" backend/ = 0`（禁止服务端协议引用，但允许客户端 SDK 引用）
- **改动原因**：来源 [MCP-23, MCP-24] 指出 MCP 1.4（2025-11）已标准化异步 Tasks 和 OAuth 作用域名，客户端 SDK 引用是合理演进路径
- **影响评估**：轻度（仅验收标准措辞调整，不影响功能边界 NB-1）
- **决策类型**：PM 可直接决定

## B. F-003 教学策略升级 相关

### [S-002] 调度算法明确采用 FSRS
- **指向条目**：PRD §3.1 F-003.2 遗忘曲线
- **问题描述**：当前 PRD 未明确调度算法选型，存在自研风险（重蹈"AI 凭理解运行引擎"覆辙）
- **建议改动**：F-003.2 验收标准增加 "调度算法 = FSRS（py-fsrs 库 ≥ 0.16.0），非自研"
- **改动原因**：来源 [FEY-06] 指出 FSRS 在 9,999 个 Anki 收藏集、3.5 亿次复习基准上对 99.6% 用户优于 SM-2；Anki 已将 FSRS 设为可选默认；自研投入产出比低
- **影响评估**：轻度（仅算法选型，不影响功能边界）
- **决策类型**：PM 可直接决定

### [S-003] Agentic RAG 增加复杂度路由
- **指向条目**：PRD §3.2 F-008 Agentic RAG
- **问题描述**：当前 PRD 仅要求"重检索 3 轮 + 70% 阈值"，未考虑成本控制；Agentic RAG 成本是基本 RAG 的 5-10 倍
- **建议改动**：F-008 验收增加 "复杂度路由：仅 20-30% 查询走代理路径，其余走标准 RAG"
- **改动原因**：来源 [ARA-01, ARA-08] 指出生产成本最佳实践是"复杂度路由 + 更小编排模型 + 有界迭代 + 提前退出"
- **影响评估**：轻度（设计原则，不影响验收结果）
- **决策类型**：PM 可直接决定

### [S-012] 抗幻觉改用 NLI/LLM 法官
- **指向条目**：PRD §3.1 F-003.5 抗幻觉
- **问题描述**：当前 PRD 模糊要求"置信度 < 阈值时强制重检索"，未明确"置信度"如何度量
- **建议改动**：F-003.5 明确"嵌入方法仅作辅助过滤，最终判定用 NLI 模型（如 DeBERTa-v3-large-mnli）或 LLM 法官（Grok-4-fast 或 Claude-haiku 评分）；重检索循环 ≤ 2-3 次 + 提前退出"
- **改动原因**：来源 [HAL-16] 实验证明嵌入方法在 HaluEval 上假阳性 100%、RAGTruth 上 88%；GPT-4 LLM 法官仅 7% 假阳性；多路径防御可降幻觉引用率从 19.2% 到 3.1% [HAL-45]
- **影响评估**：重度（影响下游 LLM 成本；NLI 模型 + LLM 法官需额外算力）
- **决策类型**：PM 需与 AR-001 评估成本

## C. F-005 / F-011 桌面端与打包 相关

### [S-004] CLI 打包避免 PyInstaller onefile
- **指向条目**：PRD §3.2 F-011 一键打包发布
- **问题描述**：当前 PRD 未明确 Python 打包工具选型；PyInstaller onefile 模式触发 Windows Defender 误报且存在 CVE-2025-59042
- **建议改动**：F-011 验收增加 "Python CLI 打包采用 cx_Freeze onedir 或 Nuitka，避免 PyInstaller onefile"
- **改动原因**：来源 [PYN-19, PYN-59] 指出 PyInstaller<6.0.0 存在任意代码执行漏洞；onefile 模式自解压行为与恶意软件投放器高度相似，频繁被反病毒误报；Nuitka 执行快 2-4x、启动快 40-90% [PYN-01, PYN-14]
- **影响评估**：轻度（打包工具选型，不影响功能）
- **决策类型**：PM 可直接决定

### [S-005] 桌面端安装包大小目标调整
- **指向条目**：PRD §1.3 S6 安装包 ≤ 200MB
- **问题描述**：200MB 对 Electron（典型 120-250MB）勉强可行，对 Tauri（2-15MB）过严
- **建议改动**：S6 改为 "三平台 artifact 产出；Electron 桌面端 ≤ 250MB（软上限），Tauri 桌面端 ≤ 50MB（推荐目标）"
- **改动原因**：来源 [GUI-01, GUI-02, GUI-15] 给出三大桌面框架体积基准
- **影响评估**：轻度（验收标准细化）
- **决策类型**：PM 可直接决定（取决于 OC-1 决策）

### [S-010] 补充 WebSocket 安全架构
- **指向条目**：PRD §3.1 F-005 前端桌面应用 + §3.1 F-002 中间件层
- **问题描述**：当前 PRD 仅要求"WebSocket 推送，延迟 ≤ 1s"，未明确 Electron 主进程/渲染进程的职责划分
- **建议改动**：F-005 验收增加 "Electron 主进程管理 WebSocket 连接，渲染进程通过 IPC 调用主进程暴露的接口（安全基线：contextIsolation=true, nodeIntegration=false, sandbox=true, CSP 严格）"
- **改动原因**：来源 [WSE-01, WSE-12, WSE-29] 推荐此架构；通过 IPC 间接调用可避免渲染进程直接处理协议；FastAPI WebSocket 性能 15,000-20,000 请求/秒 [WSE-17] 足以支撑
- **影响评估**：轻度（架构细化）
- **决策类型**：PM 可直接决定

## E. F-007 pdf2zh 集成 相关

### [S-009] 翻译质量与降级路径
- **指向条目**：PRD §3.2 F-007 验收标准
- **问题描述**：当前 PRD 仅要求"10 页 PDF ≤ 60s"和"失败重试 3 次后降级到 LM Studio"，缺翻译质量保障
- **建议改动**：F-007 验收增加 "DeepSeek 翻译 ≥ 4/5（人工抽检 10%）；Ollama/LM Studio 降级仅在 DeepSeek QPS 满载时触发，3 次失败后才切换；切换后语种支持需二次校验"
- **改动原因**：来源 [PDF-12, PDF-18] 指出 DeepSeek 在成语翻译上 28% 错误率；古文/少数民族语言存在显著差距；商业文档准确率 94-98% 仅在主流程 [PDF-03]
- **影响评估**：中度（增加抽检成本）
- **决策类型**：PM 可直接决定

## F. F-008 / F-009 检索缓存 相关

### [S-013] 缓存双后端
- **指向条目**：PRD §3.2 F-009 检索/精排/缓存
- **问题描述**：当前 PRD 假设 SQLite+LRU 双层缓存，未明确生产模式下的 Redis 选型
- **建议改动**：F-009 验收增加 "缓存双后端：SQLite（默认单机模式）+ Redis 可选（生产模式）；语义缓存阈值 = 0.85-0.95"
- **改动原因**：来源 [CACHE-13, CACHE-14] 指出 Redis 亚毫秒延迟 + 1200+ QPS 适合生产；SQLite 零基础设施依赖适合本地优先；语义缓存可减少 40-90% LLM API 调用 [CACHE-49]
- **影响评估**：轻度（架构灵活性）
- **决策类型**：PM 可直接决定

## G. F-010 长期记忆 相关

### [S-011] 长期记忆选型
- **指向条目**：PRD §3.2 F-010 会话与长期记忆
- **问题描述**：当前 PRD 模糊要求"会话摘要自动生成（每 20 轮触发）"，未明确摘要算法和实体记忆存储
- **建议改动**：F-010 验收增加 "短期记忆：ConversationSummaryBufferMemory（早期摘要+近期原文）；长期记忆：LangGraph Store + JSON 持久化；跨会话实体：SQLite entities 表 + sqlite-vec 向量索引"
- **改动原因**：来源 [MEM-48] 指出 ConversationSummaryBufferMemory 是 80% 场景默认；GraphRAG 多跳精度 +35% [MEM-46]；Hindsight 达 91.4% LongMemEval [MEM-05]
- **影响评估**：重度（影响数据模型设计，需 AR-001 评审）
- **决策类型**：PM 与 AR-001 共同决策

## H. F-017 / F-018 多模态与同步 相关

### [S-014] Anki 主路径用 .apkg
- **指向条目**：PRD §3.4 F-017 多模态产物
- **问题描述**：当前 PRD 仅要求"Anki 卡片可一键导入"，未明确导入方式
- **建议改动**：F-017 验收增加 "Anki 卡片导出主路径 = genanki 生成 .apkg（无需 Anki 客户端运行）；Anki-Connect 仅作辅助通道（要求用户已安装 Anki）"
- **改动原因**：来源 [ANK-07] 指出 Anki-Connect 项目网站 2025-09 返回 404、文档缺 OpenAPI；.apkg 路径独立可靠
- **影响评估**：轻度（导出路径选择）
- **决策类型**：PM 可直接决定

### [S-015] Obsidian 同步冲突解决
- **指向条目**：PRD §3.4 F-018 Obsidian + Git 同步
- **问题描述**：当前 PRD 仅要求"笔记 MD 文件可被 Obsidian 识别并双向同步"，未考虑冲突场景
- **建议改动**：F-018 验收增加 "双向同步策略：自动 commit 每日 ≤ 1 次；vault 内部链接保护（同步时跳过 .obsidian/ 内部状态）；冲突时由 git merge 三方合并 + 用户手动仲裁"
- **改动原因**：来源 [ANK-28, ANK-45] 指出 vault > 100MB 时 Git 性能下降；Obsidian_to_Anki / Yanki 插件均需 CORS 配置
- **影响评估**：轻度（运维细则）
- **决策类型**：PM 可直接决定

- **指向条目**：PRD §4 NFR-8 规范合规

## J. OC 待确认项 决策

### [S-017] 📌 GUI 形态选型（OC-1）
- **指向条目**：PRD §7 OC-1
- **问题描述**：当前 PM 倾向 Electron，但业界数据显示 Tauri 在体积/内存/启动全面领先，PyWebView 在 Python 团队无缝
- **建议改动**：OC-1 升级为高优先级 PM 决策项。三选项对比：
  - **A. 维持 Electron**：生态成熟（npm 400 万/周）、React 熟悉、但体积 120-250MB / 内存 100-300MB / 启动 1-5s
  - **B. 改 Tauri**：体积 2-15MB（-90%）/ 内存 20-100MB（-75%）/ 启动 0.1-0.5s；但需 2-4 周 Rust 学习 + 现有 PDF 解析/学习引擎需重写为 Tauri 桥
  - **C. 改 PyWebView**：Python 原生（js_api 直接暴露 Python 对象）/ 体积最小；但 Windows WebView2 兼容问题 + 生态最弱
- **改动原因**：来源 [GUI-01, GUI-02, GUI-15, GUI-25, GUI-40] 详细对比；这是本期最关键的技术选型决策
- **影响评估**：重度（影响 F-005 整个实现路径与 S6 验收标准）
- **决策类型**：📌 PM 需决策（建议 SA-001 设计阶段做 1-2 天 POC 选定）

### [S-018] research-tool/pdf2zh 集成方式（OC-4）
- **指向条目**：PRD §7 OC-4
- **问题描述**：当前 PM 倾向 pip install -e，但未明确"必须有 pyproject.toml"前提
- **建议改动**：OC-4 决策为 "pip install -e + uv lock（pyproject.toml 路径依赖）；前置条件：research-tool 与 pdf2zh 必须有 pyproject.toml"
- **改动原因**：来源 [UVP-01, UVP-05] uv 锁文件机制要求依赖有 pyproject.toml；submodule 无法享受 uv 锁文件
- **影响评估**：轻度（实施方式细化）
- **决策类型**：PM 可直接决定

### [S-019] 状态机 vs LLM 兜底比例（OC-10）
- **指向条目**：PRD §7 OC-10
- **问题描述**：当前 PM 倾向 90% 状态机 + 10% LLM 兜底，但未明确审计要求
- **建议改动**：OC-10 决策为 "90% 状态机 + 10% LLM 兜底（带审计）；强制要求：兜底调用必带 trace_id + 输入/输出/评分写入审计日志"
- **改动原因**：来源 [DSM-02, DSM-39] 指出 71% 生产 Agent 故障位于 SDB 弱点；LLM 兜底审计是生产可靠性基础
- **影响评估**：中度（影响 F-003.6 流程引擎设计）
- **决策类型**：PM 可直接决定（与 AR-001 评审）
